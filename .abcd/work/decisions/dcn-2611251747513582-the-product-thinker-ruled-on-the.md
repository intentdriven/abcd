2026-11-25 — The product thinker ruled on the live-reservation ceiling that iss-2610231127555243 waits on, replacing the choice it put (one ceiling per person, or a count per account and machine) with two limits. First, a per-drain limit on lanes in work: each drain run holds at most this many reservations for lanes being implemented, set per repository and overridable for one run, one by default, so a drain reserves an issue, fixes it and then reserves the next, and more parallelism means more drains, one per terminal, machine or account. A lane whose pull request is queued keeps its hold, so no other drain duplicates it, but no longer counts against its drain's limit; the technical facilitator settled that reading from the cycle the product thinker described, which is the usual worker-pool shape of one lease per worker, scaled by adding workers. Second, a per-person ceiling, set in the repository's configuration and ten by default, counting every live reservation under the GitHub login across all machines and accounts, queued pull requests included, since those still keep the issue from others. It moves from each machine's own reservation.max_live to the repository so machines cannot disagree; a machine's own setting may lower it for that machine and never raise it. The fix is a later step of the intent for drives that keep working across machines, and the issue stays open until that step lands.
