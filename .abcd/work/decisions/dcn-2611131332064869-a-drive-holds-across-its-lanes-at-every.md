2026-11-13 — A drive holds across its lanes, at every depth, the hooks directory git takes at the checkout from every scope, and the git directory's info/attributes: a file by its bytes and mode, a subdirectory by its kind and then its contents, a symlink by its target's text and by what it resolves to; a tree past 1024 entries stops the drive's start. The lane's hooks pin proves the lane's hooks directory at every depth against the commit it opens on, and refuses a symlink that leaves the directory. Across its lanes the drive also holds every setting the run's fingerprint watches, at every scope, read through the runner the ask of origin uses, with http.proxy and http.sslVerify; one predicate (watchedKey) decides what is watched for both. As it starts, where the hooks directory is the checkout's own in-tree copy and the repository has an origin, the drive proves that copy against the tip origin reports and refuses to start on a difference, naming each file; a directory outside the tree, or no origin, is not proved, and the page says so. No private copy of the hooks is run in place of the repository's, since that would change how the repository works; what one account cannot hold (a change made after the read and before git runs the hook, a setting put back between the two reads around the ask of origin, what a hook runs from elsewhere, and what changes while no drive runs, beyond an in-tree copy) is stated on the implement page with the person's remedy. A run whose fingerprint an earlier build recorded reads the nested entries as a change once and stops with the existing reason; the fingerprint's schema version is unchanged. Grounds: each lane of a drain is a run of its own whose fingerprint takes the checkout as it stands, so the drive is what spans its lanes, and every change here is a refusal by the drive or a wider read, so a repository works on its own as before. To reverse: return the hooks walk and the pin to the top level, the drive's held keys to their listed families, its hooks directory to the one the repository's own settings name, and drop the proof at the start; no persisted state changes.
