2026-11-26 — The technical facilitator, under facilitator.mode auto, ruled how the spot-check trusts its own store (itd-2610301750162657, adr-2611251806496719). A cycle read back from abcd-spotcheck is verified on every read and never trusted. Its window is recomputed, not read from it: the spotcheck block as the default branch stores it at the window's start, the repository layer alone, must be the cycle's window and per-group values, and the close the default branch's first-parent line gives must be the cycle's bound, end commit and moment. Then its beacon signature verifies under the pinned quicknet key, its round is the first at or after that close on the chain's pinned genesis and period, every landing it lists is a commit of its window, its drawn lists are recomputed from that randomness over its listed populations, keyed by the window's start commit and close alone and never by the cycle's id, and its close is no later than the reader's clock plus five minutes. A cycle that fails is set aside, named in the draw's note, and its window is drawn afresh; the pre-push hook still admits it, and nothing reads it as true. A window's close is read from origin's default branch and the window's start alone, so its round, its id and its draw are the same whoever draws it and whenever. From the second window on, the start is a verified cycle's close; the first window's start is the opening's own word, within bounds every reader checks: no later than the reader's clock allows, no earlier than its commit was committed, and no later than that commit's first-parent child on the default branch was, give or take ten seconds for a forge clock behind the writer's. An opening outside them is set aside, named, and opened afresh by the next observer, and the mark keeps an opening only once that child has confirmed it. A round not yet published is reported as not yet drawable and asked for no sooner, and there is no preview and no retry to choose a draw by: nothing about the moment a draw runs chooses it. Each machine keeps a high-water mark of the last copy it verified in the person's home store; a branch that no longer holds it, deleted or rewritten, is refused in one line and no first window is opened over it (a copy that is only behind the mark, as a second clone on the machine is, is fetched first and never called rewritten), and .abcd/work/rulesets/spotcheck-protection.json mirrors the ruleset against deletion and forced pushes that the person applies. Hand-backs and decisions join a population by arrival on the branch, so a record that reaches origin after its window was drawn is drawn from in the next, and every record is in exactly one population: a record group lists its population whole, at most 1,000 keys a window with the rest left for the next, and a draw reads only the records no earlier verified cycle listed. A judgement counts toward the size only when it reads as one, of this schema version, naming the cycle, item and role its path names, with a verdict of sound or wrong. Accepted as residual: a holder of the person's push rights can still write a cycle that verifies but lists or leaves out records of its choosing, or hold a record back until a draw is known; the halving of the sample trusts every holder of push rights until the review lane settles who may judge; a window closed by changes takes its close from a committer time. The spotcheck block is read at the commit a window starts at, the repository layer alone, so neither an uncommitted value, a landing inside the window, nor one machine's own layer sizes a draw. A block that does not read there, a file that does not parse or a value misspelt or out of its bounds, counts that window by the bundled defaults, and the cycle records that it did; a read that failed for a passing reason, a git that did not answer, refuses the observation instead, so no reader counts a window by the defaults that another reads by the block. circl stays at v1.6.3, the version the module graph already required, as the facilitator ruled before; the spec's v1.6.5 is corrected to it.
