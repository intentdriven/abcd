2026-11-26 — A guard killed by a signal holds the command. When the PreToolUse hook's guard ends with an exit above 128 (a signal, which a resource limit or the host's timeout produces), the hook exits 2 with its FAILED TO RUN line instead of exit 1, so a command the guard was still judging does not run unjudged. That holds at every rung, the dogfood build's own run included: a dogfood build killed by a signal holds the command there rather than falling back to the installed release, because a signal means the guard ran and died, and nothing proves why. Any other unexpected exit, a missing binary included, keeps the loud path: a dogfood build that is not built, cannot start (126, 127) or ends with another exit than 0, 1 or 2 still falls back to the installed release, and a guard that cannot start never blocks every command. Grounds: a killed guard had started on this command and may have been about to refuse it, while one that never ran says nothing about it. To reverse: drop the exit-above-128 branch in hooks/pre-tool-use.sh at every place it judges a guard's exit (the old-folder rung, the dogfood build's own exit, the installed release judging after the dogfood build, and the plugin-root and PATH rung), and the tests TestGuardShimHoldsWhenTheGuardIsKilled, TestGuardShimHoldsAKilledGuardBesideTheOldFolder and TestGuardHoldsWhenTheReleaseIsKilledBehindTheDogfoodBuild with it.
