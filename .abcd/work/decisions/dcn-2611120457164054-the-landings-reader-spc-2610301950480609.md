2026-11-12 — The landings reader (spc-2610301950480609, itd-2610301850454860) completes dcn-2611120418288645 in two points. First, the rule that a person-push row is unattended unless a recorded approval of that commit exists holds under the human mode as well as under auto: the mode attends a merge, not a push. Second, a first-parent commit whose subject names a pull request the forge answered for and contradicted (the number names no pull request, the pull request has not merged, or it merged as another commit) is classed as the push it is, person-push in every mode, unattended unless a recorded approval of that commit exists; the row carries the forge's reason, and the forge's answer is kept in the cache so a later listing reads it again rather than reading the forge as unread. Where the forge did not answer, the row stays a pull-request row and the human mode attends it, with the listing's note saying the forge was not read. Both points replace the sentence in approach 5 that Unattended is never set for person-push. Grounds: a subject is text whoever made the commit typed, and only the forge's answer says a pull request merged as that commit; the human mode describes how the merge gate admits a merge, which a push does not pass through. To reverse it, class a contradicted row from the mode again and let the mode attend a push, in classify (internal/core/landings/landings.go).
