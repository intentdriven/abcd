2026-11-16 — Step 4 of spc-2610301431075964 reads a "schema_version" member as next to the nearest anchor in the same section (between headings outside fences), the one before it first and otherwise the one after it, where an anchor is an abcd invocation or a prose mention of an input flag, and checks the member only when that anchor names an input that carries a top-level schema_version; decided by the run for owner review

Grounds: Pages show the call, then the document it reads, so the nearest call before a JSON example is the one the example belongs to. Counting every invocation as an anchor, not only those passing an input, keeps commands/docs.md's receipt example, which follows `docs cite confirm --receipt`, from being read against `--verdict-json` further down. A section bound keeps an answers file in a later section from being read against an input of an earlier one. A bare mention names no command, so its versions come from the commands of the page's own verb first: On commands/ideate.md, `--verdict-json` is read at version 2, though `docs fidelity record` reads version 1 under the same flag. An input that carries its version in `_type`, or none, is not checked by this rule.

Reverse it by changing nextTo, sectionsOf, and inputVersions in internal/core/lint/commandpagefacts.go.
