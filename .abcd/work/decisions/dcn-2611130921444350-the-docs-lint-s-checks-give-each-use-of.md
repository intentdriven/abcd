2026-11-13 — The docs lint's checks give each use of a line below a backtick left open one of two readings (iss-2611130850006749). A use that can report something (a forbidden word, a link to check, a footnote marker with no definition, a definition never referenced, a cited URL to check) reports what it finds in the line read whole or in the line read alone, so it still reports all it reported before, and more only from the whole reading below an open run. A use that can make a finding go away (a marker that counts a definition as referenced, a definition that counts a marker as defined, a marker that counts a crosswalk row as cited, a cited URL that admits a hand-written baseline receipt) reads the line alone, on every line. Grounds: a pattern can match differently over more text, so the whole reading by itself could lose a finding; and a span the page shows as code must not make a finding go away. This corrects dcn-2611130858310110: the unreferenced-definition direction no longer reads whole, and of a crosswalk row it holds only that no line above a row changes the row's spans. Consequence: a URL cited only inside such a span is refreshed and checked against the baseline, but a hand receipt for it is refused; the page closes the span on its line. Reversal: a ruling that a hand receipt may admit a URL only the whole reading finds.
