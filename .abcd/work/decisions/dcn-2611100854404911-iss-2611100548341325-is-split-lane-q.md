2026-11-10 — iss-2611100548341325 is split. Lane q builds an audit of the git calls the hooks reach with no deadline, with a checked-in baseline counting today's reached calls. The audit refuses a reached call not in the baseline and a count above the baseline's, and fails on an entry reached fewer times or not at all until it is lowered. A line added to the baseline by hand is caught only by review of the baseline's diff; a gate refusing an added line against the merge base is a later step of the issue. A static audit cannot follow every route a value takes, so the docs, the test's comment and this record name the forms the audit matches and list the forms it does not, and never claim it follows a context however it is passed on: a universal claim is falsified by any route nobody traced, as lane p found. Cheap gaps are closed; costly ones are named. A deadline-free context passed to any context parameter of an abcd function is counted, whether or not that callee reaches git, rather than traced through the parameter: the over-count is safe in the right direction, since an entry is removed only by passing a real deadline. Later lanes bind the named reads, then the rest, lowering and removing baseline entries as they go. The docs say 'every' only once the baseline is empty. Grounds: about 800 context-free call sites, of which the reached subset is unknown; a ratchet is the usual way to migrate a large codebase step by step without a flag day. Reverse: delete the baseline and make the audit strict; widen the claim once a further route is matched and tested.
