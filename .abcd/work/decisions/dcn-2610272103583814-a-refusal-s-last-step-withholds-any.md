2026-10-27 — A refusal's last step withholds any argument the caller typed that still stands whole in it, and keeps six kinds: an argument under eight bytes, a word that is part of a command name (a suggestion such as a hyphenated sub-command is printed whole, though the word typed is only one part of it), a record id matching recordid.CitedIDRe, the one shared id grammar, a well-formed run id (loop.ValidRunID), a flag value that is a word of the flag's declared vocabulary, and a relative path to something that exists in the working directory. The decision named the first three; the run id, the flag vocabulary and the working-directory path were added to the step later, so that a refusal can name the run, the word the caller chose and the overlapping path. Grounds: one step at the error boundary covers every verb, including a site no per-site rewording reached; shorter arguments are counts, letters and short words whose every occurrence would otherwise be rewritten; a command name, in whole or in part, and a well-formed id are what a refusal must name to be usable; and matching whole words only keeps a short argument from rewriting the inside of a longer word. A verb that writes its own --json document ahead of the error object is outside the step, so its own wording must not repeat the argument (build's key check is changed for that reason). Any typed word outside these six kinds is still withheld. Decided by abcd-0b (technical, delegated); the command-name rule was widened to a part of a name when the explain verb was reviewed.
