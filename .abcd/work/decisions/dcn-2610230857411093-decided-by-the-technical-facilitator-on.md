2026-10-23 — Decided by the technical facilitator on delegation (coordinator ruling, 2026-10-23), on iss-2610230016561927 (a build run serialises every lane on the previous lane merging): the finding's cause is authoring, not code. A spec step's needs line is already honoured, and a step with none waits for every earlier step (ruling DR6b), but only 5 of 169 specs on the default branch declared any needs line, so nearly every run defaulted to fully serial. Remedy, in order: first, intent ready and the spec's record-lint warn on a spec of two or more steps with no needs line on any step, saying the steps run fully serial and naming the fix, and the planning page and interviewer ask for each step's needs; a warning, never a refusal. Second, stacked readiness (a dependent lane starting once its predecessor is reviewed and landed on the run's own branch) is captured as its own record and draft intent for planning, not built now. Rejected: a default derived from footprints, running a step with no needs line in parallel when its packages are disjoint from every earlier step's, because file overlap misses logical dependencies (step 3 calls a function step 2 adds, in another file) and a wrong parallel step costs more than a serial one. Backfilling needs lines on the open specs is captured separately.
