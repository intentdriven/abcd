2026-11-07 — A drive carries on across a harness update only where the new file carries the signing team the start verified, and stops elsewhere, refining dcn-2611062148440653. What a launch shows says what it holds, not who wrote the file, so a proof alone cannot admit a file: the system verifies the team before anything runs the new file. Where no team can be verified, as on a platform or an install whose file the system cannot verify, or where the start kept none, the run stops with a line saying why and what to do. New contents at a path the run holds are no update and stop the run. A proved file that has gone, or a name that now resolves to a different file, waits and resolves again, since an upgrade leaves that for a moment; a file that stays gone ends the run at the outage's limit or the bound. A new file's failed proof has up to three tries, minutes apart, before it ends the run, since a status can read as failed under load and each update on a long run would otherwise risk ending it; a run's first proof keeps its one.
