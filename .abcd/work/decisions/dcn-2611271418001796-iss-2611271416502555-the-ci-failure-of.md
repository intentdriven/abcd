2026-11-27 — iss-2611271416502555 (the CI failure of TestARejoinDuringASlowReplayStaysBounded) is a real defect, not a tight deadline, so the code is fixed and the test's 3 s wait is kept. Grounds: coder/websocket's Conn.Close waits up to 5 s for the page's close answer, holding the read lock under a context the relay cannot cancel; once that Close has begun, CloseNow only waits for it, so the grace timer's abort (cancel plus CloseNow) ended the socket only when a read under the relay's context happened to be in progress. A connection closed while its read loop was still between reads therefore lived 5 s, past the test's 3 s wait; TestTheCloseGraceBoundsTheCloseHandshake reproduces it deterministically (5.00 s against a 300 ms grace) and the CI run took 0.77 s for everything before the wait, so the runner was not stalled. The fix keeps the hijacked net.Conn on each peer (peer.accept wraps the ResponseWriter's Hijack) and abort closes it, ending any wait at once. Reverse by reverting the commit that resolves iss-2611271416502555; the alternative, a polling wait in the test, would have hidden a socket outliving its grace by 4.5 s.
