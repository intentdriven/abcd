2026-11-27 — itd-2611252049031692: this decision supersedes dcn-2611270231482648. Where the merge queue rebases (REBASE), and wherever the merge method is not known (a re-arm, which reads no ruleset mirror, or the gate land asks at the local head before its push when the mirror there cannot be read; it reads the same rule as the enqueue that follows, so a merging queue keeps an arming that enqueue makes again), the merge gate arms nothing for a pull request with any commit in tip..head that touches .abcd/config.json (git rev-list --full-history tip..head -- .abcd/config.json), whatever its reads at the head and in the merge say, and the note says the person lands it on the forge's page; under REBASE that is a refusal, where the method is not known an answer not read. MERGE, SQUASH and no merge queue (an empty method from a rule that was read, armed as a merge commit) land the merge's tree, and keep the reads at the head and in the merge alone. The replay of the head's commits onto the tip is removed, and with it its git 2.45 floor. Grounds: fail closed rather than rest on forge behaviour abcd cannot observe without publishing, which commits a forge's rebase replays (git rebase skips one whose patch is already upstream) and in what order it replays a head that holds a merge commit; the replay agreed with neither in every case, so the ground dcn-2611270231482648 gave, that replaying a commit already upstream can only add a conflict, does not hold. The cost is that a rebased branch changing another key of the file is landed by hand. To reverse: once an observation of the forge's rebase on both questions is recorded, restore the replay (each commit merged onto the tree so far with its parent as the merge base) in the order and with the skips that observation shows.
