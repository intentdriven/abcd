2026-11-21 — A running interview's tripwire now watches every symbolic ref under the common git directory's refs/ (iss-2611012144422634, iss-2610040739124513), refining dcn-2611210502346647. That decision judged the pre-push gate on HEAD alone and stopped only on shut to open, so a role could write refs/remotes/origin/x naming the checkout's own branch while the gate already read open, or naming refs/stash while it read shut, and the person's next commit or stash would then be held by a remote-tracking ref and pushed with no preflight. Before and after each dispatch the reading records each loose symbolic ref by its name and target, read from the files, since git's listings skip one whose target does not exist, bounded at 500,000 entries walked with only the first bytes of a plain ref read. One made, changed or removed stops the interview, whatever the gate reads, unless it is a remote-tracking ref naming a plain ref under its own directory, as git remote set-head, a clone or a fetch writes refs/remotes/<remote>/HEAD; nothing else is exempt. The other moving targets were checked: the packed refs cannot hold a symbolic ref, since each line is an object name and a ref name or a peeled tag; a link under refs/ is recorded by its text and never exempt, since git reads it as a symbolic ref or follows it, and one leading to a directory refuses the reading, as does a refs/ that is not a directory; a reftable keeps symbolic refs in binary tables git's listings drop dangling ones from, so a repository keeping its refs there is refused; the checkout's own branch, when it is itself a symbolic ref, is followed to five levels as git follows it, and a link on that chain refuses the reading; the shallow file only cuts history, so it can shut the gate, never open it; replacement refs, grafts and the commit-graph are already off as the hook sets them; per-worktree refs (refs/worktree, refs/bisect, refs/rewritten) in a linked worktree's own git directory are not read by the hook's remote-tracking listing.
