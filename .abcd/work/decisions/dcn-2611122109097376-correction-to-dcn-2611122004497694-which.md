2026-11-12 — Correction to dcn-2611122004497694, which this supersedes: the page readers pair an inline code span on each line alone and mark a line unsure on the lines below a backtick run that an earlier line of its stretch leaves with no closer, to the next blank line outside a fence or comment (a blank line inside one also ends it), and after the run on its own line; each reader then takes the side that is safe for it. The spec readiness filter blanks no span on those lines below the run, the run's own line keeping its spans, and reads a span over a line break as prose. The comment walk opens a comment at an opener that is the first thing on its line, at up to three columns, whatever the line's state, and where the line is unsure any other opener with no closer on its line makes the page read whole from that line, which the build refuses and record-lint reports. The scope-condition and hand-audit readers, the stamp and the prose-citation rule pair spans on every line alone and read comments as before, and the stamp refuses a record whose comments read two ways. A backtick behind an odd run of backslashes opens no span. Grounds: reading more is the safe side for the readiness filter but not for the comment walk, which decides where sections and fences end, nor for readers that count a quoted verdict or marker as given; two reviews of the earlier ruling found both. Reversal: adopt a markdown renderer as a dependency, on the person's word, and pair spans as it does.
