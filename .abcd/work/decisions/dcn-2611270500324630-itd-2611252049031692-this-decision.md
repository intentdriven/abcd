2026-11-27 — itd-2611252049031692: this decision supersedes dcn-2611270345293001. The merge gate skips its test for commits touching .abcd/config.json only where the ruleset mirror at the default branch's tip exists, is read, and names a merge queue that merges or squashes (MERGE or SQUASH). Where it names a queue that rebases, the gate refuses a pull request with such a commit; where it names no merge queue, there is no mirror, or it is not read (a re-arm), the answer is one not read, nothing is armed and the note says the person merges it on the forge's page. A merge commit counts as touching the file only when its file is none of its parents' (git diff-tree --cc names the path), so a branch that merged the default branch's own change of the file is not held for it, while an evil merge is; every other commit counts when it changes the file against its parent. The build loop's gate reads the merge rule at the same tip it reads the mode at, not at the lane's base. Grounds: the mirror is the repository's own committed declaration, so trusting one that positively names a merging or squashing queue is the line; its silence or absence proves nothing about the forge, which may gate the branch with a queue the mirror does not name. Ignoring a merge that takes one parent's file keeps a branch that merged the default branch armable, since any change such a merge carries is in a commit of its own, on the tip or in the pull request. Cost: where the mirror names no queue, a pull request touching the file is landed by hand. To reverse: read the forge's live ruleset, or its merge-queue fields on the pull request, and skip the test where the forge says there is no queue or one that merges or squashes.
