2026-11-28 — iss-2611270325497482: the stop check judges each check by its newest run, and counts a run with no start time (the zero instant the forge client prints for a queued run) as newer than any run that has started, while runs it cannot order (two at one instant, two not started, or entries naming no check) are all kept and judged as before. Grounds: a queued rerun of a failed check is the forge's newest verdict-to-be, so the check is pending rather than failing, and keeping what cannot be ordered errs toward reporting a failure rather than hiding one. To reverse, change newestRuns in internal/core/autonomy/forge.go to drop unstarted runs from the ordering, and the matching cases in forge_checks_test.go.
