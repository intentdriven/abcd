2026-11-28 — iss-2611270325497482: the stop check judges each check (a check run by its workflow and name, a commit status by its context) by its newest run, and leaves a run out only when it had finished (a readable, non-zero completedAt) at or before the start of another run of the same check. Runs whose windows overlap are concurrent and are all judged: matrix legs given one display name, or one workflow run for push and for pull_request, share the key without being a run and its rerun. A run with no start time (the zero instant the forge client prints for a queued run) counts as starting after every run that has, so it supersedes any run that has finished; runs that cannot be ordered (two at one instant, two not started, one whose end is unknown, or entries naming no check) are all kept and judged as before. A commit status carries no completion time in the forge client's output, so it is read as ending the moment it was created, which keeps the newest-by-time rule for statuses; the forge lists only the latest status per context anyway. Grounds: a queued rerun of a failed check is the forge's newest verdict-to-be, so the check is pending rather than failing, and keeping what cannot be shown superseded errs toward reporting a failure rather than hiding one (review note on forge.go:90). To reverse, change superseded in internal/core/autonomy/forge.go, and the matching cases in forge_checks_test.go.
