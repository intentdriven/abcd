2026-11-13 — Fix round 2 of iss-2611131308266006 follows dcn-2611131438383140 on four rulings. First, every read a drive's hold depends on has three outcomes and no fourth: an answer it holds; none, where git itself says so in a form the code recognises exactly; or a stop at the config stage that names the read and why, when git fails, does not finish in time, or answers in a form abcd does not take, such as a hooks path holding a newline. No such read is ever taken as unchanged, and one that did not finish is never named as a change. Second, one table in the code names every constructor of a git command a drive can run and the environment it uses, a test fails when a constructor the drive reaches is not in it, and the hold reads the settings, the files they include, the attributes files and, where that environment's commands run hooks, the hooks directory, in each distinct environment of the table, holding a file or directory two environments share once; so the landing push and the reservation's pushes and fetches, which run in the person's own environment with hooks on, are held too. Third, the start's wait on an origin it cannot reach is the drive's own wait: it ends at the stop, the until bound, the check before a stage and the idle limit, and reports the lost network to the run's shared outage and waits on its probe, as a lane's ask does. Fourth, the drive adds no git floor: where git does not know the names of the attributes files, the global one is found as git finds it and the system one beside the system settings file, and where such a git names no system settings file the system attributes file is not held.
