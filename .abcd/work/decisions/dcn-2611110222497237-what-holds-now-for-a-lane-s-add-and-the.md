2026-11-11 — What holds now for a lane's add and the drive's hold on the checkout's hooks, stated in one place; it restates dcn-2611110149369936, dcn-2611102104588687 and dcn-2611102203415224, and the two older ones are corrected in part by dcn-2611110107010491. A lane's git worktree add runs in the checkout, so it runs the post-checkout hook of the hooks directory git takes there (for a relative core.hooksPath, the checkout's own working-tree copy), with the new worktree as its directory, for a new branch and a standing one alike; it reads objects as stored, so the lane holds the tree its commit stores. The standing-branch check and the core.hooksPath named on the add's command line refuse a lane whose hooks differ before a worktree is made and pin the directory judged; neither stops that hook from running. Across the lanes of one drive, the drive reads the checkout's hooks directory as it starts, through the fingerprint's reader, and holds hashes of it in memory; just before each lane's add the worktree stage reads it again, and an entry added, removed or changed since the start, and still so at that read, refuses the lane before that add. Its limits: (a) the directory is read just before the add, a change made after that read and before git runs the hook is not seen, and nothing holds the directory through the add; (b) the directory read is the one the repository's own settings name, so with a relative core.hooksPath set only in global settings the copy the add runs is not the one read; (c) what is compared is each top-level entry, a file by its bytes and mode, a subdirectory by its kind only and a symlink by its target text, up to the reader's cap of 1024 entries, and nothing a hook sources or runs from a subdirectory or from elsewhere is held. Elsewhere (a step the host runs, a single build, a drive started again) the copy is taken as it stands at the run's first check, so it must not change between runs, and nothing enforces it. When a standing branch moves while git adds its worktree, the stage removes the worktree only where a real directory, not a symlink, stands at the lane's path and git lists a worktree there on the lane's branch; otherwise, or when git's removal fails, the step is refused and what stands is left, and a step taken again while the lane's worktree stands adopts it, judged by its hooks only. Grounds: the earlier records claimed more than the code holds, and a recursive hash of the directory is left for a later change. To reverse: nothing to undo in code; this record only restates.
