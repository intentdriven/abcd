2026-11-06 — Unattended work on one machine keeps a drain and source builds in separate accounts, the drain on the latest cut release, so a bad source build cannot reach the driver. This carries on dcn-2611031720012399, which moved the main work to the account running the latest build and kept a second account on the latest release. In abcd's own checkout it is an exception to the source-checkout rule in AGENTS.md and the DOGFOODING domain of `.abcd/rules.json`, neither of which names one. It covers one thing: the process `abcd drain --drive` starts and what that process runs as its own binary, namely the driver's reads and record writes, the hooks on a stage's profile, the load gate in front of a lane's preflight, and the widen command a lane's brief names. Everything else stays under the rule: any abcd verb a person or a session types in a source checkout, and a lane's agent, whose brief carries AGENTS.md as the lane's base holds it. The lane's own tree still runs in a lane, through its agent's `scripts/abcd.sh` and its `make preflight`, so a bad source build on the default branch fails that lane rather than the driver. The limit on a stale binary is that a drive is restarted on each cut, which keeps the driver at most one cut behind the default branch. Within that distance two things refuse what it gets wrong: a lane's preflight judges what the driver wrote with the tree's own gates, and the issue reader refuses a frontmatter property it does not know. Nothing refuses a change in how the tree decides that the driver has not yet got, and that waits for the restart.
