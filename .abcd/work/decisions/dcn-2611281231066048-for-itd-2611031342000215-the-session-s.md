2026-11-28 — For itd-2611031342000215, the session's technical call on the session-start reset (decision 34; step 2 of spc-2611281205023617), answering the correctness review's finding that the reset as planned cleared a question a live session still held open. The question marker gains a second line naming the session whose question the guard admitted (the hook payload's session id). The session-start hook sets the mode back to managed and clears the marker only when the marker names the stored word and either names the starting session itself (a resume, whose question tool call is gone) or names a session occupancy.Live no longer lists (a crash, a killed terminal, or a clear, which gives the host a new id). A marker naming another live session is left alone, mode and marker both; a marker with no session line, written before the change, is reset only when no other live session started in the checkout; and where the live sessions cannot be read nothing is reset. So a question a live session still holds open is never cleared by another session's start, and its badge shows its age. Grounds: the occupancy markers already tell a live session from a gone one by its host process, and the record writers use them for the same shared-checkout case; a reset at every start would make a second session's start say nobody is waited on while an answer is still owed. The cost: a question an idle but live session holds stays on the badge, with its age, until that session answers or ends or the person sets the mode. To reverse: reset at every start where the marker names the stored word, and state that cost.
