# The status line shows each role what it needs, in a table a repository can tune

## Press Release

> The status line names one role at a time and shows that role what it needs: the person answers for the role whose item has waited longest (a blocking answer first, else the oldest review), with a red 'waiting' only in manual mode, an 'auto-merge' badge whose word follows the facilitator mode's scope as it widens, and a grey review count that warns in yellow past its thresholds. Every element (where the work is, the orchestrating session and its own figures, context, the 5h/7d windows, agents, work in progress, API spend per key against its budget) has per-view words, visibility, detail stages and a dropping order for the product thinker, the facilitator merging by hand and the facilitator on auto-merge; a narrow terminal trims detail first and drops whole items last, by the terminal width the host passes. abcd ships the table as sensible defaults and builds it configurable throughout, so the defaults can be tuned by use and a repository's maintainers can adjust them. Every element and warning also has a deterministic, machine-readable explanation (value, threshold, source) an agent can read when someone asks what a warning means. Worked out in lab lab-261103114820-bcba06f (findings F-1 to F-38, the element catalogue in state/views.md) and lab-261103115111-bcba06f (gauges and font coverage), with a live trial on the person's own status line from 2026-11-03; the terminal is the technical facilitator's surface, the product thinker's view kept until their web view ships.
