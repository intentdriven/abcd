# A stuck drain lane hands itself back

## Press Release

> A drain lane that cannot finish no longer stops the whole drain. When a lane's pull request conflicts, its step keeps refusing, or its issue turned out to be fixed already, the drain hands the lane back as stuck after a bounded number of tries, releases its reservation, says why, and moves on to the next issue. Lanes waiting on a merge are read from their pull requests each move, so one that closed, left the merge queue or started to conflict stops holding its issue and is named. Lanes merge the default branch before they land and regenerate generated files rather than conflicting on them.

## Why This Matters

A drain opens one lane at a time and waits on it, so a lane that can never finish stops the whole drain. On 2026-10-16 that is the ordinary state, not an edge case. A lane whose pull request conflicts at arming, one the land fence stops, and one whose brief is refused because the issue was already fixed all read to the drain as still in progress, and every later move answers "drive" that lane. The only way out is removing the run's directory by hand (iss-2610161015368630). Lanes parked waiting on a merge are renewed from local state alone, so a pull request that was closed, dropped from the merge queue or started to conflict keeps its issue reserved, counted against the cap of ten, for as long as the drain runs (iss-2610161015381750). And lanes from several accounts conflict on the same generated files: of 259 merges to main since 2026-10-01, 54 touched the generated CLI reference, 29 the surface manifest and 18 the brief's surfaces page, while no lane merges the default branch before it opens its pull request (iss-2610161015410527).

An unattended drain on several accounts reaches each of these within hours. Each one leaves a drain that looks alive and opens nothing, which costs a person a whole run to notice.

## Mechanism

_Facilitator-on-delegation, 2026-10-16: the product thinker delegated the planning decisions of this bundle; this claim is the facilitator's, grounded in the evidence of the issues it closes._

We expect a drain to keep moving past lanes that cannot finish, because the drain reads each lane's progress from evidence that changes: the refusals the run records, and the pull request's state on the forge. It does not read a local stage that never moves. After a bounded number of identical refusals the lane goes to a dead-letter hand-back, as a queue redrives a message after its maximum receive count. And a lane that merges the default branch before it pushes, and again whenever its waiting pull request starts to conflict, with its generated files regenerated by its implementer, cannot stay in conflict on those files. The forge ignores the merge drivers a local merge would use, so the merge has to happen on the lane's branch. It would be shown wrong if, in the first week of drains on two or more accounts, a drain stays on one lane for more than the stuck bound plus one move, a closed or conflicting pull request keeps its issue reserved past the next move, or a drain lane's pull request conflicts on a generated file alone.

## Scope Conditions

- Holds for lanes driven by `abcd implement step`, whose refusals are recorded in the run's state. A lane driven by hand outside the loop is not read. <!-- cond: cond-2610161044463127 -->
- Holds where the forge answers one pull-request listing per drain move. A move that cannot read it renews nothing new and says so, and the next move reads again. <!-- cond: cond-2610161044469748 -->
- Holds for generated files the repository declares as generated in `.gitattributes`, read from origin's default branch. An undeclared generated file still conflicts, and the lane hands back. <!-- cond: cond-2610161044462911 -->
- Holds for conflicts confined to declared generated files, which the lane's implementer regenerates under the host's permissions. Any other conflict hands the lane back for a person, as a conflicting pull request does today. <!-- cond: cond-2610161044466579 -->

## Acceptance Criteria

- **Given** Maya's drain lane whose step has refused the same way three times, or has refused at one stage for an hour, **when** Maya's drain makes its next move, **then** it hands the lane back as stuck, naming the refusal, releases the lane's reservation, and opens the next eligible issue's lane in the same move. (iss-2610161015368630)
- **Given** a lane that has waited ninety minutes for its preflight receipt, or through an outage, **when** the drain moves, **then** the lane is not handed back as stuck, because a wait is not a refusal. (iss-2610161015368630)
- **Given** a lane whose brief is refused because its issue is already resolved at the lane's base, **when** the drain next moves, **then** it hands the lane back at once, without waiting for the stuck bound, since the refusal cannot change. (iss-2610161015368630)
- **Given** a lane that has been handed back as stuck, **when** a person runs `abcd implement step --discard` on it, **then** the run is discarded, with no run directory removed by hand. (iss-2610161015368630)
- **Given** Maya's drain has a lane parked waiting for its pull request to merge, and that pull request has been closed, **when** the drain makes its next move, **then** it releases the lane's reservation, hands the lane back, and names it. (iss-2610161015381750)
- **Given** a parked lane whose pull request has started to conflict, **when** the drain makes its next move, **then** it stops renewing that lane's reservation and names the lane in its next move. (iss-2610161015381750)
- **Given** several parked lanes, **when** the drain makes a move, **then** it reads all their pull requests in one call to the forge. (iss-2610161015381750)
- **Given** a parked lane whose pushed head is not on the default branch and whose pull request is still open and mergeable, **when** the drain moves, **then** the lane is renewed and named as waiting, never skipped silently. (iss-2610161015381750)
- **Given** Bob's lane merged first and changed the generated CLI reference, and Maya's lane, cut earlier, changes it too, **when** Maya's lane reaches its sync before the push, **then** it has merged origin's default branch, the conflict on the generated file has gone back to the implementer as a fix round, and the validated result's pull request is mergeable without a person resolving it. (iss-2610161015410527)
- **Given** Maya's pull request is open and waiting, and another merge to the default branch makes it conflict on a generated file, **when** the drain next moves, **then** the lane syncs again instead of being handed back. (iss-2610161015410527)
- **Given** a lane whose merge of the default branch conflicts on a file that is not declared as generated, **when** the lane syncs, **then** nothing is pushed, and the lane is handed back naming the conflicting files. (iss-2610161015410527)

## SOTA

Facilitator-on-delegation, 2026-10-16:

- **Dead-letter redrive.** Message queues move a message that keeps failing to a dead-letter queue after a maximum receive count, as Amazon SQS does with `maxReceiveCount`. This is mature. Adopted, path 2: three identical refusals, or sixty minutes refusing, hand the lane back as stuck, and waits by design are not counted.
- **Keeping a branch current with its base.** GitHub's "update branch" and merge queues merge the base into a pull request so that it is tested as it would land. Both are mature. Adopted, path 2: the lane's sync merges origin's default branch before its push, and again while its pull request waits.
- **Generated files.** GitHub's `linguist-generated` attribute marks generated files, and lockfile merge drivers regenerate them on a local merge. The forge ignores merge drivers (iss-2609240646538011), so path 2 takes the attribute and leaves the regeneration to the implementer's fix round.
