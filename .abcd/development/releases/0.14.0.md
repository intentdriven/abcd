# Release 0.14.0 (2026-10-12)

A person who types `/abcd:` sees only the commands people use. Commands only agents run, such as the guard that judges a shell command, are hidden from the menu and keep their names; typed in full, the host says to ask the agent, which still runs them. The menu holds 15 commands where it held 35, and the commands it merged go with no alias: four of them now live under one `library` command. (itd-2610090831227812)

> "I used to scroll past twenty entries I would never type to reach the three I use," said Iris, a product thinker. (itd-2610090831227812)

`abcd build next` chooses the next intent to build, says why on the record, and builds it: the readiest planned intent, oldest among equals, with a grounds entry naming who else was considered, why each lost and what would show the pick wrong, committed as the lane's first commit. A spec lists its steps, and `abcd build` lands them one at a time, each its own lane and pull request. (itd-2609211116005482, itd-2609212103565953)

> "I used to open the run file every morning and pick by feel, then forget by Friday why Tuesday's pick was that one," said a product thinker who had planned forty-eight intents and could build one a day. (itd-2609211116005482)

> "The implement verb was three lanes in the spec's order, and nothing had a word for the three," said a technical facilitator reading the run file. (itd-2609212103565953)

When abcd sets up a project, it asks the owner whether abcd should keep parts of the project's README.md current or leave the README entirely to them. On a yes it offers the parts it can read from the project itself: a line naming the licence, links to files such as the changelog, contributing guide and security policy, a table of contents and, for a project declared public, live release and build badges. It never writes the title and never touches the owner's own words. (itd-2610031348087517)
