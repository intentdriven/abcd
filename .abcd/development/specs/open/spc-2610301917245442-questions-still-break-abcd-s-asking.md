# Every question abcd asks passes its check before the person sees it

## Summary

Delivers itd-2610230756259215, which resolves iss-2610230745597968 and iss-2610301855200679. One decision function in `internal/core/question` judges a question as the guard hook judges it today, and two callers share it: The hook, and a new read-only sub-verb, `abcd guard question`, that reports every fault grouped by rule and tab, the rows of each tab, what the hook would do with the draft in this checkout now, the binary's version, and the input ready to ask. The hook's refusal loses its ten-part cut and names every rule on every tab it hits, in the words the verb shows, with one line pointing at the verb and the question-writing agent. A question is abcd's only when a header is in abcd's number grammar (`Q1`, `Q1a`, `Q2/5`), whatever the status line says; the older role-word form (`Product Q2`) is still read as abcd's. The `abcd:question-drafter` agent becomes abcd's question-writing agent: It writes, runs the verb, fixes every fault, and checks again, at most five checks to a part, splits what does not fit into numbered parts, and returns only a draft the verb exits 0 on, or a refusal to the agent that called it. The GRILL text and the generated pages say so, and the brief's invariant 1 binds to every question carrying abcd's header. Three recorded labs are the evidence for the criteria that rest on a live model.

### Approach

1. **The decision function.** `question.Decide(f Fields, s State, l Limits) Verdict` is lifted out of `presentQuestionGate`. `State` is what the hook reads before it decides: Whether the person is away and whether that record was read, the mode's person and whether the store was read, whether the badge shows, and the binary's verbs. `Verdict` carries the outcome, the findings, the per-tab addressee with an `addressee_changes` note where an older-form chip would re-set the mode (decision 15), the rows split of every tab, whether the result is partial and which stores and rules it could not apply, and whether the verdict depends on state (decision 5). The outcomes are decision 3's: `admit`, `admit-with-rows-note`, `refuse`, `refuse-away`, `admit-unchecked`, and `unchecked`. Order is the hook's today: Away first (`refuse-away` before any limit), then the header test, then the limits. `admit-unchecked` is any call with no header in abcd's grammar, in every mode state, since decision 36 supersedes the parenthesis in decision 3. `unchecked` is each fail-open path: An away record or mode store that could not be read where the rules needed it, marked `partial` with `unread` naming the store and the rules it decides (the register rule for the mode, every rule for the away record). The rows split is exported as `question.Rows(t Tab, l Limits) RowSplit` with the fields `header_and_frame`, `question_text`, `options` and `total`, the figures `splitRows` already computes.
2. **One store reader.** `questionState(cmd, cwd) (question.State, []unread)` in `internal/surface/cli` holds the reads both callers make: `awayAtQuestion`, `mode.Root`, `ahoy.Managed`, `mode.HasTier`, `mode.ReadAt`, and `verbsOf`. The hook calls it and then `Decide`, and acts on the verdict as it acts today: A deny for `refuse` and `refuse-away`, the marker and the mode for an admission where the badge shows, the rows note for `admit-with-rows-note`, `questionFailOpen` for `unchecked`. The writes stay in the hook, after the decision, so the verb can never reach them.
3. **The verb.** `abcd guard question [<file>|-] [--ask] [--json]`, a sibling of `guard check`, registered beside it. It reads the draft from the file or standard input under `maxHookStdinBytes`, calls `questionState` and `Decide`, and writes nothing (decision 9): No marker, no mode, no branch record, no log. Its help line is in the house form: "Check a draft question as the hook will judge it: Writes nothing; refuses an unreadable draft, a store it cannot read, and any finding." Exit 0 when there is no finding and every store was read; 1 on any finding, a rows overrun alone included; 2 when the input is not JSON, is over the cap, has neither shape, or when a store the rules depend on could not be read, even with no finding (decision 8, invariant 16), and, once spc-2610301950037469 lands, when a question limit the repository or the person set is refused (with `refused` and no `ready`) or a layer of the question limits could not be read (the partial result naming the file).
4. **Two input forms, chosen by the flag.** Without `--ask` the input is the host question tool's `{"questions": [...]}`, decoded as `decodeQuestions` decodes it (unknown keys kept, a known key of the wrong type unreadable). With `--ask` it is `question.Ask`, decoded with unknown fields refused, since abcd owns that schema; `question.Check`'s structural findings are reported under the rule `structure`, and the limits run over `Ask.Fields()`, so a missing `Now:` line is named by the limits check and never invented (decision 14). `ready` is the input's own bytes for the host form, so `multiSelect` and every key the check does not read survive, and the composition through `Fields` rendered as the host's input for `--ask`; it is absent when the outcome is `refuse` or `refuse-away` (decision 7).
5. **The JSON.** `_type` `abcd/question-check/v1`; `version` from `core.Version`; `hook` (the outcome); `depends_on_state`; `partial` and `unread`; `addressee` per tab with `addressee_changes`; `findings`, each with `tab`, `part`, `rule`, `value`, `limit`, `remedy` and `refuses`; `by_rule`, one entry per rule and tab with the first echoed value and a count; `rows` per tab and `rows_limit`; `ready`. spc-2610301950037469 adds three fields to the same type, so its name does not change: `limits` (`rows`, `label_words`, `description_sentences`, the figures in force), `limits_source` (the same three keys, each `bundled`, `.abcd/config.json`, or `~/.abcd.noindex/config.json` where a personal value tightened it), and `refused` (`key`, `value`, `bounds`, `file`, and for a personal value that loosens `limit` and `limit_file`) on the refusal path; `rows_limit` equals `limits.rows`. The text render prints the outcome, the rows per tab, the grouped finding lines from the shared renderer, and the pointer line.
6. **The grouped refusal and one renderer.** `question.GroupFindings(findings) []Group` folds findings into one group per rule and tab, in the order the first finding of each appeared, keeping one echoed value and a count. `question.RenderGroups(w, groups)` writes one line per group: The tab, the rule, the echoed value, the limit, the remedy, and "and N more such lines" when the count is above one. The deny becomes: The head line counting the refusing findings; the group lines for the refusing rules; `rowsNotRefusingLine` and the rows groups; and one pointer line, "Check the next draft with `abcd guard question` before asking it, or draft it through the abcd:question-drafter agent, which does." `maxRefusalParts`, the "and N more part(s)" line, and `modeMadeAbcds` go (the mode no longer makes a question abcd's). The bound is the rules times the checked tabs plus the call-level finding and the three fixed lines, because the check already stops at four tabs and four options. The rows note names the verb beside the drafter.
7. **The header grammar, and the mode.** The grammar becomes `^(?:(<role>) )?Q[1-9][0-9]*[a-z]?(?:/[1-9][0-9]*)?$`: An optional role word from `ChipRoles` for the older form, then `Q`, a number, an optional part letter, and an optional total. `question.IsAbcds(header, l)` replaces `hasAbcdChip`'s test; `ChipRole` keeps returning the role word, and returns none for the number form. Rule 1's limit and remedy name the number form (`"Q1"`) and say the older form is still read. The hook decides abcd's question by the header alone (decision 36): A call with no header in the grammar is `admit-unchecked` in every mode, and the branch at guard_question.go lines 175 to 186 goes with it. The register rule follows the mode for the number form: The hook passes the mode's person where the badge shows, and `Unnamed` elsewhere, where `forProductThinker` already falls back to an older-form chip's role word. The mode writes: An admitted call with an older-form chip still sets the mode from the chip (`chipState`); an admitted number-form call sets nothing and is marked open under the current mode, so the answer's reset returns the mode the agent set with `abcd mode product-thinker` or `abcd mode facilitator` before asking (decision 37) to managed. Invariant 1 is reworded to bind to every question abcd asks through the host's question tool, each of which carries abcd's header, and to say that the header is what the guard checks the question by.
8. **Pages and the brief.** `commands/guard.md` gains a `question` section beside `check` and `hook` and rewrites the question paragraphs of `hook` (the header rule, the grouped refusal, the pointer); `commands/mode.md` says the agent sets the mode before a number-form question and the answer resets it; `commands/intent.md` and `agents/planning-interviewer.md` move their examples from the chip to the number form with the mode set first, which `TestPluginQuestionBlocksNameTheAddressee` already accepts as a setter. The brief's guard chapter gains the `question` row in its sub-verbs table, the verb's exit rules beside `guard check`'s in "What a person gets back", and a rewritten question gate section; `.abcd/development/release/surface.json` and `docs/reference/cli/commands.md` are regenerated with the tree (decision 18).
9. **The writer.** `agents/question-drafter.md` keeps its name (decision 31) and is rewritten as the question-writing agent. It labels every draft with a number header, resolves the binary as every plugin page does, runs `abcd guard question` after every edit, and returns the verb's `ready` as `questions`, its `rows`, its `version`, and `checked_by: abcd`. It loops until the verb exits 0, at most five checks to a part (decision 32). It never refuses for length: Material too long for one screen is split into numbered parts as decision 33 says, independent decisions as tabs of one question (up to four) and a dependent part as the next question; too many answers are the dependent case, Q1a offering the first answers and "None of these", which leads on to Q1b with the rest and "Decide later"; one decision whose material alone is too long is quoted shorter and faithfully, with every answer's gain and cost kept, or split into the decisions it holds. Its refusals have three causes, each returned to the calling agent only: A missing or contradictory part of the brief, the verb's exit 2 (reported as the refusal and never a reason to count by hand, decision 11), and five checks spent, carrying the verb's last findings. Where the installed binary has no `guard question`, it returns `checked_by: hook-only` and counts nothing by hand (decision 21); only where the host gives it no shell does it count by hand, `checked_by: hand`. In abcd's own checkout it runs the verb from the source tree, as the repository's own rule says, and records the version it reports.
10. **GRILL.** `AskingRules` changes as decision 17 (revised) allows: The drafter rule says the writer runs `abcd guard question` on each draft, returns what the check counted, and loops until it is clean, that the agent running an interview asks only what the writer returns and never writes or edits a question itself, and that a host with no agents checks its own draft with the same verb before asking; the layout rule names the number form (`Q1`, `Q1a`, `Q2/5`) and says the older form is still read; the last rule says the agent sets the mode to the addressee with `abcd mode product-thinker` or `abcd mode facilitator` before a question and the answer sets it back. Every rule that opens "In abcd's own interviews" keeps those words. `make asking-sync` regenerates both pages, and `renderDrafter` tells the writer to label every draft, run the verb after every edit, and return its rows, ready input and version, keeping the hand count for a host with no shell.
11. **Labs.** Three labs on one pinned binary and one fixed material each (decision 22): A managed snapshot repository with the plugin binary and no abcd checkout. Each lab's probes are three recorded runs, each transcript kept in `state/probes/<probe>/`, and a criterion passes only when all three pass. The pass rules and the fixture files are written into the lab's `INTENTION.md` before any run, and the harvest is captured into a research note.
