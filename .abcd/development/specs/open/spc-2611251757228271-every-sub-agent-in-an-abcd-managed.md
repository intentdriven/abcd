# every-sub-agent-in-an-abcd-managed

## Summary

This spec delivers itd-2611251725190796 in two steps, built on one branch and landed by one pull request. Step 1 tells every sub-agent, as it starts, where the repository's conventions are and which commands print abcd's rules, and has its stop keep one line for what it skipped. Step 2 has the guard refuse a sub-agent's write until it has read the conventions file, as the product thinker ruled on 2026-11-25 (dcn-2611251823160636). abcd's four cold-reading agents are left out of both (the intent's decision 4). The sibling spec spc-2611251757236507 wires the same verb, `hook subagent-start`, into the settings `abcd start` hands a session: the verb's name is all the two specs share, and nothing here touches `internal/core/runner`.

The file paths, the verb, the manifest's figures, the gap's id, the fact names, the marker's file name and the held git commands are fixed by this spec. Function names are suggestions, and the fixed words of each message are the implementer's, held to the content this spec lists.

### Approach

**The manifest and the shim.** `hooks/hooks.json` gains a `SubagentStart` event: one group, one command, `sh "${CLAUDE_PLUGIN_ROOT}/hooks/subagent-start.sh"`, `"timeout": 10`, no matcher and no `statusMessage`. `hooks/subagent-start.sh` is the body `hooks/subagent-stop.sh`, `hooks/stop.sh` and `hooks/stop-failure.sh` share, copied by hand: the old-home stop first, then the plugin-root binary, then the owned `PATH` binary, then the dogfood rung, and never `bootstrap.sh`. It differs from them in three places only: the event named in its comment, the verb `hook subagent-start` (five times), and its last line, `abcd: the plugin binary is missing, so this sub-agent was not told where the conventions and the rules are — install per https://github.com/intentdriven/abcd#install`, with `exit 1`. No generator writes the files under `hooks/`: searching `cmd/`, `scripts/` and the Makefile finds none, and the tests in the footprint are what hold the copies to one shape. The file is committed with mode 100644, as its siblings are.

**The verb.** `abcd hook subagent-start` (`newSubagentStartCommand`, in `internal/surface/cli/hook_subagent_start.go`, registered in `newHookCommand` and in `applyHookPlaneFailOpen`) reads the host's payload: `session_id`, `cwd`, `agent_id` and `agent_type`. The host shows a start hook no task. It answers in this order, under one deadline:

1. A payload whose `agent_type`, with one leading `abcd:` taken off, is in `oracle.SelfContained()` ends the hook: nothing on stdout or stderr, no fact written, exit 0. Those are abcd's four cold-reading agents. The test sits in `internal/surface/cli`, which imports `internal/core/oracle` already: that package depends on `rules` and `history`, so neither can ask it.
2. The payload's `cwd`, else the process directory, is asked for its checkout with `managedRootContext(ctx, cwd)` (`internal/surface/cli/hook_away.go`). A checkout abcd does not manage ends the hook: nothing on stdout, nothing on stderr, nothing written, exit 0.
3. The rules are loaded as the prompt router loads them: `rulesRootContext(ctx, cwd, …)`, then `rulesForHook(root, …)`. A set whose kill switch is on (`RuleSet.Disabled`, from the repository's file or the machine's) ends the hook the same silent way. A set that will not load is the hook failing (below), which is what the loader's own contract says of a file it refuses.
4. The conventions file is `AGENTS.md`, else `CLAUDE.md`, as a regular file at the checkout root. It is found with `os.Stat`, links followed, and never opened, so nothing in it, its check word included, can reach the output. With neither, the message says nothing of a conventions file and still carries the commands and the domains.
5. The sub-agent's `told` fact is written (below), and then the message.

Items 2 to 4 are one function, `subagentConventions(ctx, cwd, errOut) (root, file string, applies bool, err error)`, which the guard's hold reuses in step 2, so the start hook and the guard cannot disagree about where the conventions apply.

**What a repository abcd does not manage is.** The rules loader has no such test of its own: `abcd rules` in a plain git repository with no `.abcd/` prints the thirteen bundled domains, and `rules --prompt` recalls them (checked on 2026-11-25 in a scratch repository). The test reused is the one every silent hook already asks, `managedRootContext`: a `.abcd/` directory at the checkout root, or a linked worktree whose main worktree has one. `TestHookStopUnmanagedRepoSilent` and `TestAwayHooksLeaveUnmanagedRepoAlone` pin it for the other hooks.

**What is sent.** stdout is one JSON object, written once and whole, with HTML escaping off, as `emitPrompt` writes the prompt router's:

```text
{"hookSpecificOutput":{"hookEventName":"SubagentStart","additionalContext":"<the message>"}}
```

On the installed host (2.1.332) a start hook's plain stdout is not delivered to the sub-agent; only this field is. The message carries, and carries nothing else:

- The conventions file: its name, that it is read first, that it stands at the root of the worktree the sub-agent works in, the root this hook looked in, and that a sub-agent given another worktree reads the copy at that worktree's root. The hook cannot do better: the payload carries the session's `cwd` and no worktree of the sub-agent's.
- The two commands, since no one command prints the rules a task recalls (iss-2611251739436752): `<abcd> rules --prompt "<your task in one sentence>"`, which names the domains the task recalls, and `<abcd> rules <DOMAIN>`, which prints one domain's rules.
- The names of the domains in force: `RuleSet.Active()`, in its sorted order, with their count.
- From step 2, one sentence saying that the guard refuses the sub-agent's file writes, and the git commands that record or send its work, until a call of its own has read the file.

It carries no rule's text, no word of the conventions file, and nothing from the payload but the directory. An example, for this repository:

```text
abcd: for a sub-agent starting in this repository.
Conventions: read AGENTS.md at the root of the worktree you work in first. This hook looked in /path/to/worktree; if you were given another worktree, read the copy at its root.
Rules: abcd's rules are not sent to you; fetch them from that root.
  scripts/abcd.sh rules --prompt "<your task in one sentence>"   names the domains your task recalls
  scripts/abcd.sh rules <DOMAIN>                                 prints one domain's rules
Domains in force (19): ATTRIBUTION, BUGHUNT, COMMITTING, CONCURRENCY, DECOMPOSITION, DOCUMENTATION, DOGFOODING, GRILL, INTENTS, ISSUES, LEAVING, LIFEBOAT, LOAD, OPINIONS, PII, ROADMAP, SCRATCH, SECURITY, SHELL
```

**Which binary the commands name.** Where the checkout root is abcd's own source tree (`abcdrepo.LooksLikeSourceTree(root)`, and `scripts/abcd.sh` is a regular file there), the commands name `scripts/abcd.sh`, run from the worktree root: an installed release or a dogfood build of another commit is never what a sub-agent in abcd's checkout is sent to. Everywhere else, where no `scripts/abcd.sh` exists, they name the absolute path of the hook's own executable (`osExecutable()`, the seam in `internal/surface/cli/staleusage.go`): the binary the shim's ladder chose, so it exists and is the version that named the domains. A path, the executable's or the root's, is written in single quotes where it holds a space, and is left out where it holds any byte outside letters, digits, the space and `/ . _ - + @ ~ , : =`: the commands then name bare `abcd`, and the sentence naming the root is dropped. Domain names need no such care, since the loader accepts only `^[A-Z][A-Z0-9_]*$`.

**The limit.** The whole stdout document is held to `rules.InjectionBudgetBytes` (9,500 bytes, under the host's 10,000). The loader caps neither how many domains a rules file declares nor how long a name is, so every name cannot be promised to fit. When the names would take the document over the budget, the list is replaced whole by the count and the command that lists them (`<abcd> rules`), and stderr says so. No name is ever cut, and no partial list is sent.

**The bound and a failure.** The deadline is `subagentStartBound`, five seconds, set at the top of `RunE` before stdin is read, under the ten the manifest declares. The work runs beside a timer and its output is buffered: stdout is written only when the work finished inside the bound. A failure is an unreadable payload, a rules file that will not load, git not answering before the deadline, a `told` fact that cannot be written, a panic (recovered), or the bound itself. On a failure stdout stays empty, stderr carries exactly one line (the helpers' own diagnostics are buffered and folded into it or dropped, newlines flattened), and the exit is 1: never 0, and never 2, which a Go panic would give and the host reads as blocking on other events. The sub-agent starts all the same. A spent deadline in a checkout that does not look managed (`looksManaged(cwd)`, which runs no git) stays silent at exit 0, as the other hooks do. The failure is counted in the lane marker (below) with the kind `start-failed`. The failure path runs no git: the store is the one the session-start hook noted for the session (`history.SessionRepo(session_id)`), and where there is none, the one line says the failure was not counted. Every git call the verb makes takes the hook's context, so `internal/surface/cli/testdata/hook-git-baseline.txt` gains no line.

**The sub-agent's facts.** abcd keeps what it knows about one sub-agent of one session beside the session ledgers, in the folder `stateFolder` opens (`~/.abcd.noindex/rules-state/`, or `ABCD_RULES_STATE_DIR`), in `internal/core/rules/subagent.go`. A leaf is the hex SHA-256 of `subagent`, the session id and the agent id, NUL-separated, plus a suffix naming the fact: `.told`, `.passed`, `.held`, `.unjudged` or `.judged`. Each fact is one small JSON file, written once and whole with `fsutil.WriteFileAtomicInRoot` at mode 0o600 and read with the guarded read `LoadState` uses. No fact is rewritten from a read, so two hooks answering for one sub-agent at the same moment cannot lose one another's write. The facts are not fields of `SessionState`: the prompt router rewrites that file whole on every prompt, and the reset hook removes it at each session start and compaction, either of which would drop a fact while its sub-agent still runs.

`told` holds the conventions file's name (empty for none), the root looked in, and who wrote it (`start` or `guard`). A reader takes the file's name from a `told` fact only when it is `AGENTS.md`, `CLAUDE.md` or empty: a fact naming anything else is one that cannot be read, and at the guard that is unjudged. A payload with no usable `session_id` or `agent_id` (`idScalarRe`) gives nothing to key a fact on: the sub-agent is still told, no fact is written, and it is never judged or held. The agent's type is stored through `safeTextScalar` and printed through `termsafe.Sanitize`, as the stop's lineage is.

The facts need no sweep of their own. The reset hook's `PruneState`, run at a session start or a compaction of any session on the machine, removes every file of that folder last written more than seven days before (`StateTTL`), and a fact is written once, so that is seven days from its writing. A sub-agent that outlives its facts is asked afresh: at its next write the guard tells it and judges it from its transcript again (items 5 and 7 of the hold), and a stop that finds no `told` fact keeps no line. The brief describes `rules-state/` as the rules loader's per-session ledgers alone in three places (`04-surfaces/01-ahoy.md` once, `05-internals/03-configuration.md` twice): each gains the sub-agents' facts.

**The stop's reading.** `hook subagent-stop` (`internal/surface/cli/hook_subagent.go`) reads the sub-agent's `told` fact. A sub-agent with none was never told, and gets no line: that is every sub-agent in a repository abcd does not manage or whose rules are off, every cold-reading agent, and a sub-agent of a plugin with no start entry that never came to the guard. For one that was told, the judgement is made on the bytes the hook already holds, by `history.JudgeSubagent` in `internal/core/history/subagentreading.go`, over the calls the sub-agent made: the `message.content[]` items of type `tool_use` (their `name` and `input`) on lines whose top-level `type` is `assistant`. No other line is read: `api-request-blob` lines copy those blocks, and `attachment` lines name the conventions file whenever the host loaded it.

- Only lines holding `"type":"assistant"`, with or without a space after the colon, are decoded, and the decoded line's own top-level `type` decides. On host 2.1.332 the key is written with no space, it is not at the start of the line, and each call is a line of its own (read on 2026-11-25 from one sub-agent's transcript: no assistant line spaced its key, and none held two calls). A name is looked for in the decoded string values of `input`, at any depth, never in the line's raw bytes.
- The conventions file is read when the input of a call that is not itself a write holds the file's name with no letter, digit, `.`, `_` or `-` on either side of it. A file-reading call on `/any/dir/AGENTS.md`, a shell `cat AGENTS.md` or `sed -n 1,40p ./AGENTS.md`, and a search for the name all count. A call that writes does not, so a refused write of the file is never its own reading, and neither is a shell line that reads the file and commits. What a write is comes from one predicate the caller passes in: the host's file-writing tools in step 1 (`isFileWriteTool`), widened by the held git commands in step 2.
- A lane's brief is read when a call that is not a write names it: a path that ends in `.abcd/.work.local/run`, a run id, a lane id and `brief.md`, in that order with nothing between and no path element after. The caller passes `loop.RunRelDir` and `loop.BriefFileName`, since `implement/loop` imports `history`. That file is the only one of a run's that carries the conventions (`brief.go`, `issuebrief.go`); a round's reviewer, fix, sync and judge briefs, and a plan review's, lie deeper and do not count. The stop drops the file from a briefed sub-agent's line on the judge's word, with no fact of the guard's needed.
- The rules command is run when a shell call's `command`, split into words with single quotes, double quotes and backslashes honoured, holds a word whose last path element is `abcd` or `abcd.sh`, followed by the word `rules`. The two commands are recognised exactly as the start message printed them, a quoted path with a space included.

One line is kept for a sub-agent that skipped either: its type, its id, and which was missing. It is one line per sub-agent: a `judged` fact is written with the line, and a later stop of the same sub-agent, which the host sends when one is resumed, keeps none. With no `agent_transcript_path` in the payload, or a transcript `readSettledTranscript` cannot read, or one over `maxTranscriptBytes`, the line says the sub-agent could not be judged, and why, from a closed set. A `told` fact the guard wrote (step 2) reports the file only, since that sub-agent was never given the commands. The reading runs before the stage, recovers its own panic, and returns nothing: the hook still exits 0 on every path and stages exactly as it does today, and the stop refuses nothing.

**Where the line is kept and counted.** The line goes in the history lane's marker mechanism: a new marker, `subagent-readings.json`, beside `stage-misses.json` in `laneDir`, written under the same file lock and atomic write `noteMissAt` uses, at 0o600. It holds a count of every line ever kept, the count already reported, the first and last times, and the newest fifty lines, each with its time, the agent's type and id, a kind from a closed set (the file unread, the rules command not run, both, could not be judged, or the start hook failed) and, from step 2, what the guard did, from a closed set of its own (held, could not judge, both, or neither). The start hook's failure path takes this lock with a one-second timeout, so the bound and the count together stay under the manifest's ten seconds. The session-start hook reads no lane marker today, only the pending directory's (`TakePendingMiss`), so counting there is new code: it gains one read of this marker for the repository it starts in, adds one notice carrying the number of lines kept since the last notice, and records that number as reported, under the lock, so each line is counted once. `abcd history staged` lists the kept lines after the stage-miss note, newest first. Under `--json` the envelope stays the array it is and the lines go to stderr, as the other two notes do. `--all-repos` is unchanged.

**ahoy.** `detectHookManifest` raises a second gap, `hooks.subagent_start_unwired`, when the manifest is otherwise sound (`verifyHookManifest` returns nothing) and no `SubagentStart` entry reaches `hook subagent-start`, read through to the script as `eventHasCommand` reads the others. It is plugin-owned, machine-scoped, not required and not resolvable, with the step `Update the plugin.` A missing or malformed manifest stays `hooks.manifest_missing` alone. The fixture manifests the other ahoy tests stand on gain a `SubagentStart` entry, so no existing test's gap set moves.

**The guard's hold (step 2).** The guard hook's payload type gains `agent_id`, `agent_type` and `transcript_path`. On host 2.1.332 a pre-tool-use payload for a call made inside a sub-agent carries the first two and the main session's carries neither (probed by the planning session on 2026-11-25). A new arm, `subagentHold` in `internal/surface/cli/guard_subagent.go`, is asked before `fileWriteGate` for the host's file-writing tools (`Write`, `Edit`, `MultiEdit`, `NotebookEdit`), and for the shell tool once the session root has resolved, when `guard.RecordActs(command)` names a held git command. A shell command in which it names none goes no further into the arm: no fact is read and none is written. The arm answers in this order, and anything but the last line lets the call go on to the guard's existing checks unchanged:

1. No `agent_id`: the call is the session's own, or the host has not said whose it is. Not held, and no store is read.
2. A drive's stage (`stageActive()`): not held.
3. A cold-reading agent, by the start hook's test on the payload's `agent_type`: not held, and no store is read.
4. The sub-agent's `passed` or `unjudged` fact exists: not held.
5. No `told` fact: `guardGitStalls(cwd)` is asked first, and a stall is unjudged; then `subagentConventions` is asked under a `guardGitBudget` context, since a context alone does not bind the rules load. Where the conventions do not apply (not managed, rules off), nothing is held and nothing is written. Where they apply and a conventions file stands, the guard writes `told` itself, so a sub-agent whose start hook failed, or whose plugin has no start entry, is held as well, and its refusal is what tells it.
6. No conventions file: not held.
7. The sub-agent's own transcript is read once with `readTranscript` (one guarded read, capped at `maxTranscriptBytes`), not with `readSettledTranscript`, whose waits are the stop's. Its path is `<transcript_path without .jsonl>/subagents/agent-<agent_id>.jsonl`, and it is judged by `history.JudgeSubagent` with the same predicate the stop uses. A reading of the conventions file there: `passed` with the reason `read`. A reading of a lane's brief: `passed` with the reason `briefed`. Neither is held.
8. No reading: the guard writes `held` and refuses the call with the host's deny (`denyCall`). The reason names the conventions file and the root looked in; says that any call of a tool that does not write and names the file passes (the host's reading tool, `cat <file>` in the shell, a search for it); says that the read goes in a call of its own, since one in the same shell line as the held command is not counted and one sent in the same turn may not be; and says to send the write again after it.

Whatever cannot be judged is not held: an agent id that is not a plain scalar, a fact store that cannot be read, a `told` fact naming a file other than the two, git stalling or not answering inside the budget, a rules file that will not load, a payload with no absolute `transcript_path`, and a transcript that is absent, unreadable or over the cap. Each writes `unjudged` with its reason, from a closed set, where there is a key to write it under, and item 4 then lets every later call of that sub-agent through: abcd does not come back to hold a sub-agent it has said it could not judge, and it pays for git and a transcript read once. The stop's line is where this is said. The guard buffers its stderr and the host discards it when the hook answers a plain allow at exit 0 (`answerGuardHook`), so a line of the guard's own is seen only when its answer is something else.

For a told sub-agent with no reading, the stop's line says its writes were held (a `held` fact), or that they could not be judged and so were not held (an `unjudged` fact, or a write in its transcript with no fact of the guard's at all, which is what a payload that named no sub-agent leaves behind). With both a `held` and an `unjudged` fact, the line says both.

**The shell commands that count as a sub-agent's write.** The git commands that make a commit or send one: `commit`, `merge`, `rebase`, `cherry-pick`, `revert`, `am`, `pull` and `push`. `guard.RecordActs` (`internal/core/guard/recordacts.go`) reads each command of the line after the guard's own tokenizer, steps over assignment words and git's global options with their values (`gitValueOptions`), and takes the subcommand by position, so `git stash push`, `git log --grep=commit` and `echo git commit` are not held. It does not take `branchActsIn`'s first rule, under which one word a substitution or a variable prints anywhere in the command makes it no act: built that way, the hold would pass `git commit -m "$(cat <<'EOF' … EOF)"`, the commit line a host's agent ordinarily writes. Here such a word is allowed as the value of a global option that takes one, and anywhere after the subcommand; as the program word, an option word or the subcommand it reads as no act. A line the tokenizer cannot split reads as no act. A command run through a wrapper (`env`, `sh -c`, a script, an alias) is not seen. `abcd land` and `gh pr merge` send work with none of these commands and are not held, since what they send was held at its commit. No other shell command is held: no closed reading of a shell line tells a write from a read, and an edit made through the shell is held at its commit. These cases were put through the tokenizer on 2026-11-25, on a copy of the tree since removed, and split as the paragraph needs:

- Held: the here-document commit above; `git -c abcd.assistedBy=X:y revert abc`; `git -C "$wt" commit -m x`; `cd /wt && git add -A && git commit -m x`; `git pull --rebase`; `FOO=1 /usr/bin/git --no-pager push origin HEAD`.
- Not held: `git $opts commit`; `git "$sub"`; `$g commit`; `env GIT_AUTHOR_NAME=x git commit -m x`; `sh -c 'git commit -m x'`.

**How the build loop's agents are told apart.** A drive's stage is a host process abcd started with the stage's environment, which `stageActive()` reads: nothing in it is held, its settings wire no start hook, and its brief carries the conventions. A host-delegated build's implementer is a sub-agent like any other to the host, and is told apart as a reading is: its transcript names its lane's brief in a call that is not a write, and that brief (`internal/core/implement/loop/brief.go`) carries the conventions whole. The fact `passed: briefed` is kept so later calls answer from it. A run in the checkout exempts nobody: a sub-agent started by hand beside a running build is held like any other, and so is a round's fresh implementer or reviewer until it has read the conventions file or the lane's brief.

### How each criterion is met

The intent's criteria, in the order it lists them. Each test named is written first and watched fail.

1. The hook names the conventions file and the commands, never the check word, and says nothing to a cold-reading agent: `TestSubagentStartNamesTheConventionsFileAndTheCommands`, `TestSubagentStartFallsBackToClaudeMdThenSaysNothingOfAFile` (a conventions file that is a link is still found), `TestSubagentStartNamesTheWorktreeItLookedIn` (a subdirectory of a linked worktree), `TestSubagentStartNamesTheCheckoutsOwnScriptInAbcdsSourceTree`, `TestSubagentStartNeverCarriesTheCheckWord` (a fixture file holding a check word, and one with mode 0 that is still named), and `TestSubagentStartSaysNothingToAColdReader` (`abcd:cold-reading-detection` and the bare name: stdout and stderr empty, exit 0, the fact folder empty). The fact store under them, in `internal/core/rules`: `TestSubagentFactsAreKeptPerSessionAndAgent` (written once, keyed by both ids, mode 0o600, and removed by `PruneState` at its age) and `TestSubagentToldFactTakesOnlyTheTwoFileNames`. `TestHooksManifestNamesLiveSubverbs` holds the manifest's entry to a verb that exists.
2. It fits the host's limit whole: `TestSubagentStartFitsTheHostLimitWithEveryDomainNamed` (every `Active()` name present, the document within `rules.InjectionBudgetBytes`, no rule text of the fixture present) and `TestSubagentStartCountsTheDomainsItCannotFitAndCutsNone`.
3. The live check is the planning session's to run, once, after step 2: "The live check" below says how. No unit test stands for this criterion.
4. A write is held until the file is read: `TestGuardHoldsASubagentsWriteUntilItHasReadTheConventions` (refused with a reason that names the file, the root and the way out; the same payload allowed once the transcript holds a reading; allowed a third time from the fact alone), `TestGuardTakesAShellReadAsAReading`, `TestGuardHoldsTheGitCommandsThatRecordOrSendWork`, `TestGuardDoesNotTakeAWriteThatNamesTheFileAsAReading` (a refused write of the file itself, and `cat AGENTS.md && git commit -m x`, which stays held), `TestGuardHoldsASubagentTheStartHookNeverTold`, `TestSubagentStartSaysTheGuardHoldsWrites`, and `TestRecordActsReadsTheGitCommandsThatRecordOrSend` in the core, on the cases listed above.

9. Nothing is added where abcd does not manage the repository or the rules are off: `TestSubagentStartAddsNothingOutsideAManagedRepository` (stdout and stderr empty, exit 0, no file under the home) and `TestSubagentStartAddsNothingWhenRulesAreSwitchedOff` (the repository's switch and the machine's).

### The live check

The planning session runs it once, after step 2, on the installed host, and both receipts come from that run. It is run in a scratch clone of the branch, with this tree's build as the binary of a scratch plugin root that holds this tree's `hooks/`. The launch is the print form of the run's own start script with its `--append-system-prompt` left off, so that nothing hands the session the conventions:

```text
CLAUDE_PLUGIN_ROOT=<scratch plugin root> claude -p --setting-sources "" \
  --settings '{"hooks": <the hooks object of hooks/hooks.json, SubagentStart included>, "enabledPlugins": {<each built-in plugin of the host>: false}}' \
  --tools "<the shell, the file tools and the sub-agent tool>" \
  -- "<start one sub-agent: it writes one file before anything else, then answers the conventions file's check word>"
```

The commands in `hooks/hooks.json` name `${CLAUDE_PLUGIN_ROOT}`, which the host sets for a plugin's hooks. Whether it sets it for hooks handed over in `--settings` was not checked, so the launch sets it.

The check counts only when the sub-agent's transcript holds no `instructions` attachment naming the conventions file: with one, the host loaded the file into the sub-agent, and the check word proves nothing. The first receipt is `.abcd/.work.local/logs/<date>-subagent-start-live-check.md` in the main checkout, since a linked worktree's local tier goes with the worktree. It names the host's version, the date, the sub-agent's type, what the hook returned, the `cwd` the payload carried against the directory the sub-agent worked in, that the transcript holds no such attachment, the sub-agent's answer, and the line its stop kept, if any. The second receipt, beside it, is the hold in the same run: the write refused, the read, and the same write passing. A sub-agent that read the file before its first write was never held and leaves the second receipt unmet: the launch is then repeated, and the receipt says so.

### Decisions made in this spec

1. Two steps. The start hook, the stop's reading and the ahoy gap are whole without the hold, and the hold changes the guard hook, which is reviewed on its own. Both are built on one branch and land in one pull request (next section).
2. The hold reads the sub-agent's own transcript at the held call, and the pre-tool-use matcher does not gain the reading tool. A matcher that named it would run the guard's shim on every read of every session: `hooks/pre-tool-use.sh` blocks at exit 2 in the old-home stop and salvages a missing binary by download, the stage's settings in `internal/core/runner/wall.go` (not this spec's to change) would no longer match the manifest's, and an older binary behind a newer manifest would warn that every read runs unguarded. Against that, the transcript route changes no manifest line and no shim, costs nothing until a sub-agent's first write, and gives the hold and the stop one definition of a reading. Its cost is a path the host does not document. On host 2.1.332 the record of a tool call is in the sub-agent's transcript on disk by the time the call runs (read on 2026-11-25 from inside a running sub-agent), so a read made in an earlier turn is there at the write. A host that moves the file leaves every hold unjudged, which is not held and is said at the stop.
3. A sub-agent is judged at its stop from its `told` fact, not from a marker in its transcript. The host does record a start hook's run in the sub-agent's transcript, but that record is undocumented too, and the fact is abcd's own.
4. Naming is the test of a reading, at the hold and at the stop alike. A call that names the file without reading it passes, so the hold proves a skipped reading and never a careful one.
5. The eight git commands are the shell writes held, and the file tools' every write is held wherever it lands, the local tier included.
6. A sub-agent with no `told` fact is held too, on the guard's own asking of the start hook's test, so the hold does not depend on the start hook having been delivered.
7. A `told` fact that cannot be written fails the hook whole, and nothing is sent: every sub-agent that was told has a fact, and a store that cannot be written is counted and seen at the next session start.
8. A briefed sub-agent is one whose transcript names its lane's brief, judged as a reading is. A run in the checkout exempts nobody.
9. abcd's four cold-reading agents are told nothing and never held, by the type the host names for them (the intent's decision 4).
10. An `unjudged` fact is final for its sub-agent: the guard does not judge that sub-agent again, and never holds it.
11. A held sub-agent is not let through after some number of refusals. That would reverse dcn-2611251823160636 for an agent that declines to read.

### One branch, and what waits if time runs short

Both steps are built on one branch: a commit for step 1, a commit for step 2, then the close's records. `make precheck` and the narrow tests run after each step; `make preflight` runs once, on the committed tree after the close; one pull request carries the branch; and the live check is run once, after step 2. The close's records follow step 2's commit as a commit of their own, as the repository's earlier closes do, because the doc-fidelity gate reads a docs review saved for the commit the close is made on. That commit carries the trailers.

If time runs short, the spec is closed with `--remainder`, the change carries no `Delivers:` trailer and the intent stays planned, since a criterion would be unmet. What waits, first to last: the `history staged` listing and the session-start count (the marker is still written); the `start-failed` count; and the ahoy gap with its three fixtures, last, since it is what tells a person their installed manifest lacks the entry. Never left out: the cold-reading exemption, `guard.RecordActs` as written here, the final `unjudged` fact with its single transcript read, the refusal's way out, every could-not-be-judged path with its test, and the six lists that pin hooks.

### Limits the code sets

- The hook cannot know the sub-agent's worktree. The first criterion's "in the worktree the sub-agent works in" is met by naming the root looked in and telling the sub-agent to prefer its own.
- The second criterion's "the name of every domain in force" holds for every rule set whose names fit, and cannot hold for every file the loader accepts: a set that does not fit is counted and pointed at.
- The host skips a start hook's context for a sub-agent it runs with an isolated context. Such a sub-agent has a `told` fact and was not told; it is still held, and the refusal names the file.
- A hook the host kills at ten seconds counts nothing. Where a dogfood build fails, the shim runs the installed release for the same event, which can use up what is left of the ten.
- A failure is counted only where the session-start hook left a note for the session, and not in a repository that keeps its transcripts in its own checkout.
- A read and a write sent in one turn: the write passes when the read's record is on disk by then, and is held once when it is not. The refusal says to read in a call of its own.
- A sub-agent's facts are removed seven days after they were written, at the next session start or compaction on the machine. One still running then is told and judged afresh by the guard at its next write, and its stop reports the file only, or nothing if it never writes again.
- A sub-agent whose every tool writes can name the file in no call that counts and stays held; its stop's line says so, and the session that started it is never held. No agent the plugin ships is one, nor any the host listed on 2026-11-25.
- An implementer handed its brief's text in its prompt, and not the file to read, has no call that names the brief: it is held at its first write like any other and passes after one read of the conventions file or of the brief. The loop's `awaiting` line names the brief's path and does not say how it is handed over; of the 47 lane implementers in the transcript store's last 2,500 records, every one named its brief in a call (the reviewing agent's count, 2026-11-25).
- The exemption of the cold-reading agents is by the type the host names. A session that starts one of the four for other work, or a repository that defines an agent under one of the four names, gets a sub-agent that is told nothing and never held.
- The one-line sentence of `abcd guard hook` (`internal/core/surface/sentences.go`) is not reworded here: that file would be a seventh shared with the sibling spec. After step 2 it understates what the hook writes (a sub-agent's facts) and refuses (an unread write). Nothing is captured for it yet: if it reads untrue after the build, the builder rewords it where that is the one line and the file then joins the footprint, and otherwise the planning session files it.
- abcd's four cold-reading agents are told nothing, are never held, and get no line at their stop, having no `told` fact. Invariant 15 lets no repository or home path into a reading's context, and the message carries one (the intent's decision 4).
