# abcd records how each change landed

## Summary

Delivers itd-2610301850454860. The reader is a core function before it is a verb, because the spot-check (itd-2610301750162657, spc-2610301925429250) draws from it at landing time, inside a landing that has no terminal to print to.

### Approach

1. **The run's state names its admission.** `State` gains `Admitted *Admitted` (`json:"admitted,omitempty"`), with `Kind` (`drain` or `build`), `Record` (the drain rule's ADR id, the spec id, or the issue id), and `Path` (the rule record's repo-relative path, for a drain's run only). It joins schema version 16, which no release has written. `start` sets it before `writeState`: The drain passes the `drainrule.Rule` it loaded through a new unexported `Options.admitted`, set beside `lane.drain = true` (`loop/drain.go:1125`), so every lane the drain opens carries the rule the drain began under; `abcd build <itd-N>` and `abcd build next` take `build <spec id>` from `chk.Spec`; `abcd build <iss-N>` takes `build <iss-N>` from `chk.Key`. A `drain` option without a rule record (the bundled baseline) is refused at the start, naming `drainrule.Load`, so a trailer can never read `drain` with no id. The run record gets one entry at the start, `admitted under drain adr-N (path)` or `admitted under build spc-N`, as the pace and review set get theirs.
2. **Every lane makes its records commit, and the commit carries the trailer.** `landPrepare` no longer sets `RecordsDone` when the landing has nothing to move (`loop/land.go:254-257` goes); its note reads `records only the admission`. `landRecords` refuses before it touches the worktree when `c.State.Admitted` is nil, naming the field and the fix (start the run again with this abcd; a run begun before it recorded admissions cannot land under it), so no commit is ever made without the trailer. With the field, it appends `Admitted-by: drain <adr-N>` or `Admitted-by: build <spc-N|iss-N>` to the trailers after `Delivers:` and `Resolves:` and before `Assisted-by:`; when the trailer names an issue the commit's `Resolves:` lines do not, it also writes `Refs: <iss-N>`, since RS004's message half (the commit-msg hook) refuses a bare mention. When nothing is staged and the landing had nothing to move, the commit is made with `--allow-empty` and the prose `records only the admission`; the refusal at `:404-407` stays for a landing that was to move a record and changed nothing. A record-only commit carries `Assisted-by: abcd:<version>` alone (`composedAssistedBy`), since every word of it is a fact abcd computed; a commit that carries a model's prose keeps the receipts' models as today. `lane.HeadSHA` becomes the commit, so the preflight receipt, the push, the review receipt, and the merge all name it, as they name the records commit today. The pull request body (`prBody`) adds the same `Admitted-by:` line among its trailers, with the same `Refs:` rule, so a squash merge that adopts the body keeps the admission in history. The landing's refusals say what they say now; the trailer adds none.
3. **Nothing is added to a person's branch.** `abcd land` (`landing/land.go:252`) keeps writing no commit: The gate, the push, and the arming name the head the person made, and `Land` writes only the composed body in the local tier (`prbody.go`). `TestLandMovesNoHeadAndWritesNoTrailer` asserts the branch tip before and after `Land` and reads the message of every commit in `tracking..head` for an `Admitted-by:` line.
4. **The reader is a core package, `internal/core/landings`.** Its entry is `List(ctx, repoRoot, Range, Options) (Listing, error)`, and `Trace(ctx, repoRoot, sha, Options) (Trace, error)` for one commit. `Range` is `From` and `To` (full object names, `To` the default branch's tip as last fetched, `refs/remotes/origin/<default>` from `gitutil.DefaultRef`), resolved by the verb from `--since` (approach 8) and by the spot-check from its window's `from_commit..to_commit`. `Options` carries `Forge landing.ForgeCall` (nil is `landing.GHContext` bound to `ctx`) and `Worktrees` (nil lists them as `findReceipt` does). The package exports the trailer's grammar, `ParseAdmitted(message) (Admitted, bool)`, which the loop uses to compose and tests use to read, so there is one spelling. `landing` exports two seams it already has unexported: `ApprovalRecord(repoRoot, sha)` and `CommittedMode(repoRoot, commit) (mode string, found bool, err error)`, which reads `.abcd/config.json` as the commit holds it (`git show <commit>:.abcd/config.json`, bounded as `readRepoAt` bounds it) and judges `facilitator.mode` with `checkMode` (`config.go:189`), the repository layer alone and never the machine layer, since the listing reads a past commit and the merge gate's machine layer is gone with the moment. A mode the file does not set is `human`, the bundled default (`config.go:237`). `List` fetches nothing and writes only its cache (approach 6): The spot-check calls it right after its own fetch, and the verb says which tip it read.
5. **One `Row` per first-parent commit, newest first, and four classes decided in order.** One `git log --first-parent --format=%H%x1f%P%x1f%ct%x1f%cn%x1f%s%x1f%B%x1e From..To` gives every row; one `git log --format=%H%x1f%P%x1f%B%x1e From..To` gives every commit the range reaches, second parents included, from which the rows' branches are assigned in memory (each commit belongs to the first-parent row whose second-parent walk first reaches it, stopping at the first-parent line and at commits already assigned). A row holds `Commit`, `When`, `PR` (from the subject's `Merge pull request #N` or trailing `(#N)`), `MergedHead` (the second parent, or the forge's `headRefOid` for a one-parent row that names a pull request), `Class`, `Rule{Kind, ID, Path}`, `Lane` (`drain`, `build`, `unknown`, or empty for a person's push), `Approval{Seen, By, At, Source}` with `Source` one of `forge`, `local tier`, `none seen`, `forge unread`, `Mode` (`human` or `auto`, with `modeless` when the first parent holds no `.abcd/config.json`), `Resolves`, `Delivers`, `AssistedBy` (from the branch's commits' trailers, once each), `Unattended bool`, and `Reverted *Revert`. The classes, in this order:
   - `person-push`: A one-parent first-parent commit whose subject names no pull request; `Committer` from `%cn`, no rule, no lane kind.
   - `person-approved`: `ApprovalRecord(MergedHead)` found in a worktree of the listing checkout (`Source: local tier`, and the row says it was read from this checkout's local tier); else the forge's latest submitted review per reviewer, not `PENDING` and not `DISMISSED`, whose state is `APPROVED`, whose commit is `MergedHead`, and whose author is not the pull request's author, read as `countedApproval` reads a page but without the permission read, so the forge is asked once per pull request (`Source: forge`, `By` the login, `At` the review's time); else `CommittedMode(first parent)` is `human` (`Source: none seen`, rule `facilitator.mode: human`). The lane kind is shown whatever it is (decision 8).
   - `drain`: Under `auto`, the branch carries `Admitted-by: drain <id>`; rule by id and path.
   - `automatic`: Under `auto`, everything else; rule `facilitator.mode: auto` as `.abcd/config.json` held it at the first parent, by its path and commit. The row names the mode's requirement (a review receipt naming the head), never a receipt, which decision 6 says is not recoverable.
   `Unattended` is true for `drain`, for `automatic`, and for any row under `auto` whose lane kind is `unknown` or whose approval is `forge unread` (decision 9); never for `person-approved` or `person-push`. A landing from before this ships has no trailer, so its lane kind is `unknown` and its class comes from the approvals and the mode alone; nothing is rewritten.
6. **The forge, asked at most once per pull request, through the landing's own client.** For every row that names a pull request, one GraphQL document per batch of up to twenty pull requests, aliased nodes of `pullRequest(number:N){number author{login} headRefOid mergedAt body mergeCommit{oid} reviews(last:100){totalCount nodes{author{login} state commit{oid} submittedAt}} commits(first:100){totalCount nodes{commit{oid message}}}}`, run as `gh api graphql` through `landing.GHContext(ctx, ...)` (each call within `ForgeTimeout`), pinned in `internal/ghcontract` beside `PRStateQuery`. The answer gives the author and reviews (approach 5), the body (approach 7), and the commits, which are read only for a one-parent row (a squash or rebase merge): its lane kind, rule, and trailers come from those commits' messages, and with `totalCount` above the page, or the forge unreachable, the lane kind is `unknown` and the row counts as unattended. A reviews page with `totalCount` above 100 counts no approval for that row, as `maxReviews` does. A forge that cannot be asked (no client, a timeout, a rate-limit refusal, an answer that does not parse, or errors in the document) leaves class and rule to history, sets every unanswered row's approval to `forge unread`, classes no row `person-approved` by a forge review, and puts the reason on `Listing.ForgeUnread`; the verb prints it once, after the rows. Answers are cached per pull request in `.abcd/.work.local/landings/pr-<N>.json` keyed by the row's commit, so a re-run asks only about pull requests it has not read; an unread answer is never cached, and the cache holds the login a row prints, which is the local tier and never a committed file. `TestNoLoginInACommittedFile` lands a fixture with a distinctive login and asserts no tracked file carries it.
7. **The revert trace reads git's own words over the whole range.** From the second `git log` of approach 5, every commit whose body carries `^This reverts commit [0-9a-f]{7,64}` (the line `revert_pairs` reads) names a commit; the named commit is resolved to a full name, required to be an ancestor of the reverting one, and followed to its row through the assignment of approach 5 (a first-parent commit is its own row). The row is marked `Reverted{By, ByRow, Kind: "revert"}`; a revert of a revert marks the reverting commit's row the same way, as `withdrawn_by` reinstates. A one-parent row whose pull request body says `Reverts #N` or `Reverts <owner>/<repo>#N` (the forge's own revert line, read from the cached answer) marks the row of pull request N with `Kind: "forge"`. A row whose subject is git's `Revert "<subject>"` with neither line is `Kind: "untraceable"`, and it marks nothing. `Trace(sha)` resolves `sha` as a prefix, says `not on the default branch` when it is not reachable from `To`, and otherwise returns the row that brought it onto the default branch (following its first-parent assignment back however far, so a positional trace is not bounded by `--since`), with the row's class and rule, and, for a reverting commit, the row it reverts as well. `--reverted` lists the marked rows grouped by rule (`drain adr-N`, `facilitator.mode: auto`, `facilitator.mode: human`, `person-push`), each group with a count, and `untraceable` reverts in a group of their own.
8. **The verb, `abcd landings`.** A new top-level verb, a person's verb in the records group beside `status`: `land` pushes and arms and should not also be the reader's verb, and `status` lists announcements that lapse within the hour (decision 10). Flags: `--since <tag|date>` (a tag, or a date `YYYY-MM-DD` taken as the first first-parent commit at or after it; the default is the last release tag reachable from the default branch, `git describe --tags --match 'v*' --abbrev=0`, and with no such tag the verb refuses naming the flag), `--unattended`, `--reverted`, `--json`, and one positional commit for `Trace`. The text render prints one line per row, `<short sha>  #<pr>  <class>  <rule>  lane <kind>  approval <source[: by, at]>  <ids>`, then the forge note and the tip it read; `--json` prints `Listing` with stable keys (`tip`, `from`, `to`, `since`, `rows[]`, `forge_unread`), the same rows as the text. `--unattended` keeps the rows with `Unattended` set; `--reverted` renders approach 7's groups. It lands with its sentence in `sentences.go` (`"abcd landings": "List how each change landed on the default branch, with the rule that admitted it: Writes only its forge cache in the local tier; refuses no default branch or no range."`), its row in `helpgroups.go` (`groupRecords`), its page `commands/landings.md` (`block: people`), row 41 in `04-surfaces/README.md` with chapter `04-surfaces/41-landings.md` and its `## Sub-verbs` table, the regenerated snapshot and CLI reference, the new package in `internal/README.md`, and invariant 7's line for `landings` (one read of the forge per pull request, no fetch, no push). `commands/implement.md`, `04-surfaces/34-build.md`, and `35-drain.md` gain the trailer's line where they describe the records commit.
9. **What the spot-check reads from this.** spc-2610301925429250 relies on exactly: `List` over `from_commit..to_commit` with rows classed `drain` and `automatic` and `Unattended` covering every row the evidence cannot place with a person; `Approval.Source == "forge unread"` so the draw can refuse rather than guess; `Rule{Kind, ID, Path}`, `When`, and `PR` for its card; `Trace` for a card's `now`; and a `ctx` the draw bounds. All of them are exported here and none is behind the verb. The draw's bound is its own: `List` honours `ctx`, and each forge batch is bounded by `ForgeTimeout`, so a range of many unread pull requests can outlast one `ForgeTimeout`; the cache makes the second read of a window cheap, and the consumer should pass the deadline it can afford.
