# Verification Matrix

The gates abcd's capabilities are held to. A row opening **(staged)** describes a
design target: the gate is specified here and its subject has no shipped surface,
so the row is a test waiting for the thing it tests rather than a claim about the
binary. Every other row describes behaviour the binary carries today.

The table is not the whole gate set. Shipped verb families carry no row here at
all — `banlist`, `changelog`, `decide`, `docs`, `guard`, `identity`, `lint`,
`reading`, `site`, `update`, `version`, and the `abcd rules` render verb (the
rules-loader rows below gate the injection hook, not the verb) — and several
families that do have rows are covered only in part: the `ahoy` read-only
sub-verbs (`doctor`, `dry-run`, `remote`, `uninstall`, `identity-check`), the
`disembark` synthesis sub-verbs (`coverage`, `graveyard`, `plan`,
`press-release`, `principles`, `review`), `history` beyond capture (`drain`,
`list`, `show`, `staged`), `capture disposition`, and `intent
ready`/`link`/`audit ingest`. Each of those is specified in its own chapter under
[`../04-surfaces/`](../04-surfaces), and the machine-checked half of the surface
set is the `surface_coverage` rule over
[`../04-surfaces/README.md`](../04-surfaces/README.md). An absence from this table
is a gap in the table, never evidence that the capability is ungated.

| Test | What to check |
|---|---|
| Front-door wiring (CLI↔core↔plugin) | A `commands/*.md` surface shells to the binary → `internal/surface/cli` parses input → the core returns a **structured result** the door renders. Core behaviour with no front door calling it is dead scaffolding — fails the wiring check. **(staged)** the second half of the test, that the same core call is reachable from the MCP door with no logic re-expressed (adr-23), waits on that door: `internal/surface/` holds `cli` alone |
| ahoy idempotency | Run twice same version → no marker duplication, "already up to date", transparent re-confirm of visibility |
| ahoy upgrade | Bump plugin version → `config.json["meta"]` updated, marker content refreshed, no duplication |
| ahoy visibility flip | Switch private→public → `.gitignore` updated correctly, user shown resulting tracked-vs-ignored list |
| ahoy scanner probe | scanner seam defaults to the native secret/PII scan; a missing opt-in backend (gitleaks; TruffleHog when scan.deep=true) → native scan used, opt-in install offered with confirm — never a hard-fail on absence |
| ahoy rules-loader install | Marker block from the bundled defaults injected; `.abcd/rules.json` skeleton written; the prompt-router hook registered |
| Probe report | `/abcd:disembark probe` on corpus reports correct source-reader findings per repo (rich on idelphiDev, sparse on idelphiSubZero) |
| Native transcript capture | A session transcript is written to the root-SHA-keyed native local store, **redacted at write time before anything lands on disk** (the two-stage redaction model, per adr-29); the store is gitignored; an optional specstory import merges by timestamp/content hash over the same store |
| Native spec store | Directory-as-truth (adr-26): a spec's location encodes its status (`open/` → `closed/`), and `abcd spec close <spc-N>` moves it and ships its linked intent in one act. Readiness is per-intent — `abcd intent ready <itd-N>` reports it and exits non-zero when the intent is not ready. **(staged)** the dependency graph over specs and tasks, the sequencing that resolves ready work from it, and the ccpm backend round-tripping the same on-disk shape at the convention level (adr-24): `internal/core/spec` carries no graph, and `spec` registers one sub-verb |
| Recency mechanic | **(staged)** Decision changed across specs → `spec-essence.json` body=latest, earlier in `superseded_by`. No verb produces a `spec-essence.json` |
| Pass B targeting | **(staged)** chat-distiller receives only the time-windowed subset from the native transcript store; `rationale-fills.json` cites transcript filenames. The `chat-distiller` prompt is an unshipped draft under `../../research/prompting/agents/`, not one of the 15 prompts in `agents/` |
| Agent dedup | **(staged)** chat-distiller does not re-emit pitfalls already in a curated pitfalls page. Neither the agent nor the page ships |
| Agent context budget | **(staged)** Inputs over a `disembark` agent-token budget trigger stream + summarise; one-shot under threshold. `disembark` exposes no such config key and no summarising path |
| Host-delegated oracle (default) | Oracle seam with **no adapter wired** → abcd emits the prompt, the host's subagent dispatch runs it, the structured result returns to the caller; never blocks, needs no API keys (adr-25) |
| Oracle adapter degrade | **(staged)** A wired oracle adapter (native/CLI/API/MCP) that is unreachable → degrades to the host-delegated default rather than failing the run. `adapter/oracle/` is on the planned-seams list; `internal/adapter/` holds `scanner` and its `gitleaks` plug-in, so there is no adapter to make unreachable. `abcd ahoy install --oracle-backend` records the choice ahead of the seam |
| Review quality | `review/review-<manifest12>.json` has specific findings, not vague approval |
| Oracle re-review | After a fix, the audit-fix loop re-dispatches the review prompt through the oracle seam; the verdict can downgrade (SHIP→NEEDS_WORK) and is honoured; each dispatch is independent, so the loop re-primes context every iteration |
| Disembark checkpoint | **(staged)** Ctrl-c mid-`disembark pack` writes a forensic checkpoint. No `resume` sub-verb ships, and none is planned: re-running the pack starts fresh, so a checkpoint exists for post-mortem only. Where it lands is undecided (see the open question below), and it may not be `.abcd/logbook/`, which iss-73 retired |
| Disembark read-only (adr-35) | `disembark pack <source-repo> <dest>` never writes to the source: a test hashes the source tree before and after the run and asserts it is byte-identical. Pointing disembark at a repository abcd has never touched — no `ahoy install`, no `.abcd/` — succeeds |
| Disembark destination safety gate (adr-35) | `disembark pack <source-repo> <dest>` proceeds only when `<dest>` is absent, an empty directory, or a directory carrying a parseable `_provenance.json`. A non-empty directory abcd did not produce → refuse (no overwrite, no `.bak`); a malformed `_provenance.json` → refuse. Re-run over an abcd-produced `<dest>` → transparent confirm, then regenerate in place |
| Embark source lookup | `embark from <lifeboat-dir> [target-dir]` takes the path explicitly and scans for nothing; `embark probe <lifeboat-dir>` reads the same input read-only. There is no `home` shorthand — the lifeboat lands at an operator-chosen destination, never in-tree (adr-35). **(staged)** a candidate-listing `scan` sub-verb, in any form: `embark` registers `from` and `probe` and nothing else |
| Embark conflict safety | Emptiness is not the gate: a target holding unrelated files is fine. Every per-file conflict (a differing target, a non-regular target, a non-directory parent) refuses the WHOLE write and exits non-zero with one bulk conflict report; identical bytes are an idempotent skip, so a re-run is a clean no-op. `from` accepts no flags, so there is no `--force` to override the refusal with |
| Embark asset curation | **(staged)** keep=copied verbatim, adapt=user prompted with suggestion, drop=silent skip. `from` writes the four record families verbatim into their canonical locations and curates nothing |
| Embark RP workspace registration | **(staged)** Lifeboat carrying an external-tool workspace descriptor + the opt-in adapter present → user prompted to register; adapter absent → graceful warn-and-continue. No such adapter or descriptor exists in the tree |
| Round-trip | disembark on idelphiDev → embark into empty target → new repo memory+ADRs faithful subset |
| Multi-repo corpus | All milestone acceptance gates pass on each corpus repo (with documented exemptions) |
| Launch preflight | Deliberate PII fixture → `abcd launch --dry-run` (the preview is a flag on the parent, not a sub-verb) runs the secret and PII scan for real in report-only mode, prints the would-refuse finding, and exits 0. **(staged)** the hard-fail half: running the full gate suite and refusing the cut on a finding is the full-`ship` design (itd-65 + itd-72), and no artefact path is emitted with the refusal |
| Launch curated release (single repo) | Packaging **excludes `.abcd/**`** from the release artifact; `abcd launch --dry-run` proves nothing under `.abcd/` appears in the artifact manifest (adr-28). There is no second repo — the cut is a build-time filter over one tree |
| Launch manifest | Correct include/exclude, resolved from the bundler's own rules. **(staged)** a per-repo allow-file overriding them: `internal/core/launch` reads no such file |
| Launch branch mode | **(staged)** a branch-scoped cut leaving main untouched. `abcd launch` accepts `--dry-run`, and `launch ship` accepts `--changelog-json` and `--payload-dir`; no mode selector ships |
| Launch version stamp | Bump tier derived from shipped intents' `impact` with the surface-diff guardrail (adr-31); the version is stamped into the **curated release artifact** at cut time (the working tree stays unversioned — adr-19/adr-20 polarity on one tree); `marketplace.json` updated |
| Launch documentation-auditor | docs/ inspected; warn-fail surfaces user prompt before proceeding |
| Asset discovery | Prompt fires when assets found; user-supplied paths merged into curator input; `_provenance.json` records origin |
| Intent capture | `/abcd:intent "<text>"` (canonical bare quoted create, per spc-30/itd-46) runs interview → writes `intents/drafts/itd-N-<slug>.md` with press-release content + persona quote + acceptance criteria (per itd-1) |
| Intent plan | `/abcd:intent plan <itd-N>` → lints acceptance criteria → **native plan handoff** scaffolds the bidirectionally-linked spec in the native spec store (ccpm backend when wired) → injects bidirectional link → moves drafts/→planned/ |
| Intent acceptance lint | `/abcd:intent plan` on a draft missing `## Acceptance Criteria` → hard block, error message names the missing section |
| Intent ship | Shipping is spec-driven, not intent-driven: `abcd spec close <spc-N>` moves the spec `open/` → `closed/` and, as its close-hook, the linked intent `planned/` → `shipped/`. The intent's `impact` must be stamped first, or `intent_impact_valid` refuses the move. There is no `intent ship` sub-verb, and nothing runs the close for you — an intent whose code is on the default branch with its spec still open ships with no changelog line |
| Intent lifecycle hook | Closing the spec is what moves the linked intent `planned/` → `shipped/`. **(staged)** the review queue that transition was to feed: `internal/core/spec` and `internal/core/intent` carry no queue, and nothing is enqueued or backfilled. Auto-running `intent-auditor` is likewise deferred — spc-6 disowned auto-firing. The audit that ships is manual: `abcd intent audit <itd-N>` re-emits the request and `abcd intent audit ingest` writes the returned verdict into the intent's own Audit Notes |
| Intent help | bare `/abcd:intent` shows intents grouped by state with suggested next actions; same pattern across all abcd commands |
| Intent fidelity review (Role 1) | The shipped `agents/intent-auditor.md` emits both halves: per-criterion verdicts (MET/MET_WITH_CONCERNS/NOT_MET/INCONCLUSIVE) over itd-1 acceptance criteria, each with a cited `path:line` evidence pointer and a `MET_WITH_CONCERNS` refused unless it names its concern, **and** the three-bucket prose audit (honoured / diverged / missing). Manual run via `abcd intent audit <itd-N>` works. **(staged)** the itd-37 boilerplate check over a spec's Modification Grammar: no such check is in the prompt or in any lint |
| Persona registry | `.abcd/development/personas.json` is a lint registry: the `persona_registry` rule in `internal/core/lint` matches a press-release quote attribution and refuses a name the roster does not carry, which is what keeps a real name out of a record. **(staged)** picking a persona from the roster, and biasing that pick on a role hint: there is no `internal/core/personas` package and nothing selects |
| Bidirectional link drift | `internal/core/lint` warns when intent's `spec_id` and spec's `intent` field disagree; runs as pre-commit hook (and in CI) |
| Press-release oracle audit | `abcd disembark press-release` composes deterministically from the packed brief and spine, or validates host-produced press-release JSON under the cite-or-be-dropped validator. **(staged)** appending audit findings back into the composed press release as an open-questions section: the verb appends no findings section |
| Embark press-release interview | **(staged)** First embark step shows lifeboat press release + audit; user confirms/amends; amended version becomes embark contract. What ships is probe-then-write with the coverage blanks a human must answer surfaced first (itd-88 M5); the interview is M6 |

| Capture wontfix (spc-21) | `/abcd:capture wontfix iss-N "<reason>"` → file moves `open/`→`wontfix/` with `wontfix_reason` + `updated` fields populated; stdout reports `wontfix iss-N → wontfix/ (reason recorded)` |
| Capture bare render (spc-21) | Bare `/abcd:capture` → read-only status render (counts `open N · resolved N · wontfix N`, up to 10 most-recent open issues, next-action hints); no `iss-*.md` created/moved/mutated. spc-20 safety preamble (txn recovery, orphan cleanup, ledger-dir ensure) is allowed |
| Capture filtered list (spc-21) | `/abcd:capture list --open` / `--resolved` / `--wontfix` / `--all` → one line per issue (`iss-N <state> <severity> <slug>`), sorted numerically by N. Unfiltered CLI `abcd capture list` (no flag) → exit 2 with "choose a filter" message |
| Capture promote (spc-24, itd-119) | `abcd capture promote <iss-N> --grounds "<token>: <text>"` is a shipped CLI sub-verb: it mints an intent draft from the issue and stamps the pair of back-edges natively — `promoted_to` on the issue, `promoted_from` on the draft. `--intent <itd-N>` is stamp-only mode, linking an existing draft instead of minting one, and a taken back-edge is reported rather than clobbered. The same verb promotes a dispositioned reading item (`rdi-N`) into a draft |
| Capture migration (spc-22) | **(staged)** promoting a pre-ledger flat issue list into the structured `.abcd/work/issues/` ledger, with provenance naming the source file. The binary registers no migration verb, and the `dev-sync` command the row was written against does not exist |
| Rules-loader keyword recall | Prompt containing "commit" / "PR" → COMMITTING domain rules injected; unrelated prompt → zero abcd rules injected (token overhead < 200) |
| Rules-loader dedup | Same prompt three times → rules inject on prompt 1 and skip on 2 and 3: within a session the hook does not re-inject unchanged rules. The refresh is event-driven rather than turn-counted — `hooks/hooks.json` registers `SessionStart` and `PreCompact` as the two events that clear the per-session dedup ledger, so a matched domain re-injects on the next prompt.
