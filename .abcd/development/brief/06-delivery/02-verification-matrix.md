# Verification Matrix

What has to be true before a capability counts as delivered. Each row names one
check and what it asserts, so "done" is a thing somebody can run rather than a
thing somebody feels.

A row opening **(staged)** describes a design target: the gate is specified here
and its subject has no shipped surface, so the row is a test waiting for the thing
it tests rather than a claim about the binary. Every other row describes behaviour
the binary carries today.

**The table is not the whole gate set, and it never has been.** Whole verb
families carry no row here, and several that do have rows are covered only in part
— the read-only `ahoy` sub-verbs, the `disembark` synthesis verbs, `history`
beyond capture, and parts of `capture` and `intent` among them. Each capability is
specified in its own chapter under [`../04-surfaces/`](../04-surfaces), and the
machine-checked half of the surface set is the `surface_coverage` rule over
[`../04-surfaces/README.md`](../04-surfaces/README.md), a row-level presence
check, together with each chapter's generated appendix of flags and sub-verbs,
which a drift test holds to the command tree. **An absence from this
table is a gap in the table, never evidence that the capability is ungated.**

| Test | What to check |
|---|---|
| Front-door wiring (CLI↔core↔plugin) | A `commands/*.md` surface shells to the binary → the CLI front door parses input → the core returns a **structured result** the door renders. Core behaviour with no front door calling it is dead scaffolding and fails the wiring check. **(staged)** the second half, that the same core call is reachable from the MCP door with no logic re-expressed (adr-23), waits on that door: `internal/surface/` holds `cli` alone |
| ahoy idempotency | Run twice at the same version → no marker duplication, "already up to date", transparent re-confirm of visibility |
| ahoy upgrade | Bump the plugin version → the config's `meta` block updated, marker content refreshed, no duplication |
| ahoy visibility flip | Switch private→public → the gitignore updated correctly, user shown the resulting tracked-versus-ignored list |
| ahoy scanner probe | The scanner seam defaults to the native secret/PII scan; a missing opt-in backend falls back to the native scan and offers an install with confirmation, never a hard failure on absence |
| ahoy rules-loader install | Marker block from the bundled defaults injected; the rules override skeleton written; the plugin's hook manifest **read and checked**, never written: install confirms the prompt-router entries are there and reports a missing or malformed manifest as a diagnostic, and neither install nor uninstall ever edits it |
| Probe report | `abcd disembark probe` over the corpus reports the right source-reader findings per repo, rich on a record-dense repo and sparse on a bare one |
| Native transcript capture | A session transcript is written to the root-SHA-keyed native store, **redacted at write time before anything lands on disk** (adr-29); the store sits in the user's own home by default, outside every checkout, so no transcript is a candidate for a commit in the first place, and the one place it can sit beside a working tree is the gitignored local tier a user opts a checkout into by name; an optional import merges by timestamp and content hash over the same store |
| Native spec store | Directory-as-truth (adr-26): a spec's location encodes its status, and `abcd spec close` moves it and, when no open spec is left naming the linked intent, ships that intent in the same act; `--remainder <slug>` mints the follow-on spec for a partial delivery, and the intent stays planned until it too closes (adr-2609151513118583). Readiness is per-intent, through `abcd intent ready`. **(staged)** the dependency graph over specs and tasks, the sequencing that resolves ready work from it, and a companion backend round-tripping the same on-disk shape (adr-24): the spec core carries no graph, and `spec` registers one sub-verb |
| Host-delegated oracle (default) | An oracle call with **no adapter wired** → abcd emits the prompt, the host's subagent dispatch runs it, the structured result returns to the caller; never blocks, needs no API keys (adr-25). Two consecutive calls are independent dispatches, so the audit-fix loop re-primes context every iteration |
| Oracle adapter degrade | **(staged)** A wired adapter that is unreachable degrades to the host-delegated default rather than failing the run. No oracle adapter package exists, so there is nothing to make unreachable; `ahoy install --oracle-backend` records the choice ahead of the seam |
| Oracle re-review | After a fix, the audit-fix loop re-dispatches the review prompt through the seam; the verdict can downgrade and is honoured |
| Review quality | A lifeboat review carries specific findings, not vague approval |
| Disembark read-only (adr-35) | A pack never writes to the source: a test hashes the source tree before and after the run and asserts it is byte-identical. Pointing disembark at a repository abcd has never touched succeeds |
| Disembark destination safety gate (adr-35) | A pack proceeds only when the destination is absent, an empty directory, or one carrying a parseable provenance file. A non-empty directory abcd did not produce refuses with no overwrite and no backup copy; a malformed provenance file refuses; a re-run over an abcd-produced destination confirms, then regenerates in place |
| Disembark checkpoint | **(staged)** A mid-pack interrupt writes a forensic checkpoint. No resume sub-verb ships and none is planned — re-running starts fresh, so a checkpoint would exist for post-mortem only — and where it lands is undecided (see the open question below) |
| Embark source lookup | `embark from <lifeboat> [target]` takes the path explicitly and scans for nothing; `embark probe` reads the same input read-only. There is no shorthand for a well-known home, because the lifeboat lands at an operator-chosen destination (adr-35). **(staged)** a candidate-listing sub-verb in any form |
| Embark conflict safety | Emptiness is not the gate: a target holding unrelated files is fine. Every per-file conflict — a differing target, a non-regular target, a non-directory parent — refuses the **whole** write and exits non-zero with one bulk report; identical bytes are an idempotent skip, so a re-run is a clean no-op. `from` accepts no flags, so there is no override |
| Embark asset curation | **(staged)** keep copied verbatim, adapt prompted with a suggestion, drop skipped silently. What ships writes the record families verbatim into their canonical locations and curates nothing |
| Round-trip | Disembark a record-dense repo, embark into an empty target, and the new repo's memory and decisions are a faithful subset |
| Multi-repo corpus | Every milestone acceptance gate passes on each corpus repo, with documented exemptions |
| Launch preflight | A deliberate PII fixture → `abcd launch --dry-run` runs the secret and PII scan for real in report-only mode, prints the would-refuse finding, and exits 0. `abcd launch ship` runs the same gates and hard-fails instead: a scan finding, a file the bundler rejected, a version-lockstep drift or a retention refusal blocks the cut and exits 1, and a cut still carrying an open major or critical finding is refused by name. **(staged)** two of the six gates the report lists: the marker-block check and the documentation audit each report themselves unimplemented (itd-65, itd-72) |
| Launch curated release (single repo) | Packaging excludes the whole `.abcd/` namespace from the artefact, and a dry-run proves nothing under it appears in the artefact manifest (adr-28). There is no second repo: the cut is a build-time filter over one tree |
| Launch manifest | Correct include and exclude, resolved from the bundler's own rules. **(staged)** a per-repo allow-file overriding them: the launch core reads no such file |
| Launch branch mode | **(staged)** a branch-scoped cut leaving the default branch untouched. No mode selector ships |
| Launch version stamp | The bump tier is derived from shipped intents' `impact` with the surface-diff guardrail (adr-31), and the version is stamped into the **release artefact** at cut time, leaving the working tree unversioned |
| Launch documentation audit | **(staged)** The docs tree is inspected, and a warn-level failure surfaces a user prompt before proceeding. The gate appears in every launch report and reports itself unimplemented: nothing reads the docs tree at cut time and nothing prompts |
| Asset discovery | **(staged)** The prompt fires when assets are found; user-supplied paths merge into the curator input; the provenance file records origin. Nothing on the pack path looks for an asset, no sub-verb offers a path to add one, and the provenance file such a pack would write carries no origin field — the same gap the *Embark asset curation* row records from the other end |
| Intent capture | Bare quoted text runs the interview and writes a draft with press-release content, a persona quote and acceptance criteria (itd-1, spc-30/itd-46) |
| Intent plan | `abcd intent plan <itd-N>` lints the acceptance criteria, scaffolds the bidirectionally-linked spec in the native store, injects both sides of the link, and moves the intent to `planned/`. A draft missing its acceptance-criteria section is a hard block naming the missing section |
| Intent ship | Shipping is spec-driven: `abcd spec close` moves the spec and, as its close-hook, the linked intent — on the close after which no OPEN spec names it, because an intent owns one or more specs (adr-2609151513118583). The intent must end up carrying a product impact, because that is what decides the release's version: a record that already declares one keeps it, one that declares none takes the impact on the close that ships, and a close that can name neither is refused before anything moves; `--impact` at an earlier close, which ships nothing, is refused too. There is no `intent ship`, and nothing runs the close for you, so an intent whose code is on the default branch with a spec still open ships with no changelog line |
| Intent lifecycle hook | Closing the LAST open spec is what moves the linked intent; an earlier close moves nothing and names the specs that still hold it. **(staged)** the review queue that transition was to feed: nothing is enqueued or backfilled, and auto-running the auditor is deferred (spc-6 disowned it). The audit that ships is manual — `abcd intent audit` re-emits the request and `abcd intent audit ingest` writes the returned verdict into the intent's own Audit Notes |
| Intent help | Bare `abcd intent` shows intents grouped by state with the next actions to take |
| Intent fidelity review (Role 1) | The shipped auditor prompt emits both halves: per-criterion verdicts over the acceptance criteria, each with a cited evidence pointer and a concerns verdict refused unless it names its concern, **and** the three-bucket prose audit. **(staged)** the boilerplate check over a spec's modification grammar: no such check is in the prompt or in any lint |
| Persona registry | The persona roster is a lint registry: the `persona_registry` rule matches a press-release quote attribution and refuses a name the roster does not carry, which is what keeps a real name out of a record. **(staged)** picking a persona from the roster and biasing that pick on a role hint: nothing selects |
| Bidirectional link drift | A **blocker** when an intent's spec reference and the spec's intent reference disagree: the pair refuses to lint until they agree. It is part of the record lint, which runs in the pre-push gate and in CI; the committed pre-commit hook is the banned-names guard and runs no record lint |
| Press-release oracle audit | `abcd disembark press-release` composes deterministically from the packed brief and spine, or validates host-produced JSON under the cite-or-be-dropped validator. **(staged)** appending audit findings back into the composed press release |
| Embark press-release interview | **(staged)** The first embark step shows the lifeboat press release and audit, the user confirms or amends, and the amended version becomes the embark contract. What ships is probe-then-write with the coverage blanks a human must answer surfaced first |
| Capture write | `abcd capture "<text>"` writes an issue into the open ledger with its frontmatter populated and reports the id, slug and severity; defaults applied per spc-21; the slug is derived from the text unless overridden |
| Capture resolve | `abcd capture resolve` moves the issue to `resolved/` with its resolution and timestamp populated. A note, an impact and grounds are all required, and the optional intent, spec, commit and release references write the structured provenance. An unknown id and a transition conflict each have their own exit code |
| Capture wontfix | `abcd capture wontfix` moves the issue to `wontfix/` with the reason and timestamp populated, and reports it |
| Capture bare render | Bare `abcd capture` is a read-only status render — counts by state, the most recent open issues, next-action hints — and creates, moves or mutates nothing |
| Capture filtered list | `abcd capture list` with a state filter prints one line per issue, sorted by id. With no filter it exits 2 and asks for one, so the flag is the surface rather than a convenience |
| Capture promote | `abcd capture promote <iss-N> --grounds …` mints an intent draft from the issue and stamps the pair of back-edges natively; naming an existing intent is link mode, which writes both halves (`related_issues` on the intent, `related_intents` on the record), and an existing back-edge is kept first and reported rather than clobbered. The same verb promotes a dispositioned reading item |
| Capture back-link migration | `abcd capture migrate` reports, and `--apply` rewrites, every retired promote back-link into `related_intents` / `related_issues`, completing a join written from one end only; a second run changes nothing |
| Intent issue drift | `abcd intent audit --issue-drift` reports every promote join that does not read the same from both ends, warning on stderr and exiting 0; `--strict` exits 1 on any finding, and the strict form runs in the pre-push gate and in CI |
| Capture migration | **(staged)** promoting a pre-ledger flat issue list into the structured ledger with provenance naming the source file. The binary registers no migration verb |
| Rules-loader keyword recall | A prompt containing a domain's keywords injects that domain's rules; an unrelated prompt injects nothing |
| Rules-loader dedup | The same prompt three times injects once: within a session the hook does not re-inject unchanged rules. The refresh is event-driven rather than turn-counted — `SessionStart` and `PreCompact` are the two events that clear the per-session dedup ledger. Nothing counts prompts |
| Rules-loader star-command | A leading `*DOMAIN` injects that domain's rules regardless of keyword match |
| Voyage disembark history | Each pack appends one line to the operator-level voyage ledger with the manifest hash, the source name and root SHA, the destination, and the file and byte counts. The line deliberately carries no oracle backend and no verdict: nothing produces them at pack time, and an empty field would be a lie (adr-35). The full file list is not duplicated either — it lives in the lifeboat's own provenance file, pinned by the hash the line records |
| Voyage embark side | **(staged)** an embark provenance record and an optional verbatim archive of the input lifeboat. The voyage ledger has a disembark half only; `embark from` reads the lifeboat's provenance to verify it and writes no operator-level record of its own |
| Voyage no snapshot proliferation | Re-running a pack over an abcd-produced destination regenerates the lifeboat in place, so there is no accumulating archive of versioned directories; the previous manifest survives only in the voyage ledger (adr-35) |
| Grill (itd-27) | **(staged)** in full, and nothing of itd-27's interview ships: `intent` registers no `grill` sub-verb, no PRD or grill report is written anywhere, and no grill fixture set exists. One of its named lint codes does ship: `GL002`, the forbidden-synonym check, is armed as a blocker over the record and refuses a retired term used as live prose. No `GR*` code exists in any tree, so each of those is enforced by review. What the intent would gate: a Socratic interview whose questions are tagged by move, a synthesised PRD written beside its intent record, a content hash frozen at plan time that any later body edit invalidates, a planner handoff carrying the frozen PRD as primary context, injection resistance on both phases, and determinism of the question set and the resulting PRD. Its run output would land in the gitignored local tier |
| Spec-tied reviews (itd-28) | **(staged)** Review artefacts land in a per-spec review store with an index entry and the oracle backend recorded, and a re-review re-dispatches through the seam. The spec core carries no review store, and the review that ships is intent-grained |
| Three intent kinds (itd-34) | The `kind` frontmatter field is binding, set at plan time; a draft carries a reclassification history from creation; and disciplines carry no status field, which lint blocks. **(staged)** the rest: `intent plan` takes exactly one intent, so there is no multi-arg form and no shared spec with a bundle field per member; there is no reclassify sub-verb to append to the history; and the supersession path writes no kind stamp |
| Prompt linter (itd-5) | Every agent prompt carries a semver `prompt_version`, and the linter rejects a missing or malformed field |
| Prompt self-improvement preflight | Agents ship in the `0.x` band until they clear a calibration corpus, and only a measured prompt locks at `1.0.0` with its preflight outcome and delta recorded in the agent changelog. itd-81's amendment governs over the earlier lock-at-close expectation, so no agent is at `1.0.0` and none is due to be |
| Injection-canary fixture | Each agent reading untrusted input ships a canary fixture, and the check is machine-enforced: `agent_contract` refuses an untrusted-input prompt whose canary is absent, empty, a symlink, or not a regular file. Every shipped prompt carries one. **(staged)** running the canary and judging the output, which needs the golden-test harness |
| Capability scope (idea-4) | Every prompt carries `capability_scope` with its task classes and a one-line `designed_for`. **(staged)** validating set-membership against a closed enum: no enum artefact exists for the check to read (iss-265) |
| Oracle seam contract preserved (idea-4) | Adding `capability_scope` does **not** modify the oracle seam; capability-aware routing, when it ships, is a pre-dispatch selector above the seam rather than a change to it |
| Memory ingest | Ingesting a document produces typed entity and topic pages with a source class and citation frontmatter; the original is not stored unless explicitly kept, an ingest log entry is appended, and the index is regenerated. With the keep flag the original is stored under its content hash, and the lifeboat licence gate refuses to publish it without an explicit allowlist entry — launch never publishes it either, since launch excludes the whole namespace |
| Memory ingest transport | A local path or an https URL only: a plaintext source is refused by name before any fetcher runs, and the redirect policy refuses a hop that leaves https, ahead of the SSRF host guard. A credential the URL carries — basic-auth userinfo, or a query parameter whose name carries a secret in essentially every usage — never reaches the stored origin, the registry, the returned citation, or a fetch-failure message; the transport's own error, which re-prints the whole request URL, is unwrapped to its cause before it is interpolated |
| Memory write-time key judgement | A frontmatter or registry **key** a write introduces is judged by the store redactor exactly as its values are; a key carrying a blocking span refuses the whole write, and the refusal names the label and the kinds, never the key. Keys are not schema-fixed |
| Memory residue lint | A stored page, a registry leaf or a kept original carrying a span the redactor would refuse or rewrite is a blocker; the finding names the kind and the line, never the span, and the lint rewrites nothing. A degraded scanner is itself a blocker rather than an error |
| Memory quotation and source-class lints | Per-page and cumulative quotation budgets fire on contiguous quotation length and on deduplicated source coverage across pages citing one source. Single-source-class synthesis is advisory; cross-class synthesis without a weighting note blocks, as does an external page missing its licence field |
| Memory schema extension | Existing flat-named pages are not renamed; the index is generated over them and the default source class is backfilled |
| Memory bare render | Bare `abcd memory` shows status — page count by class, last ingest, recent contradictions, quotation headroom — and never mutates state |
| Provenance substrate | The source-hash registry updates on every ingest, with an SPDX licence extracted from the declared source or an explicit unknown; one registry serves every consumer |
| Modification grammar (itd-37) | **(staged)** in full. Every spec would carry a `## Modification Grammar` section with its three sub-headings and the ripple axis, checked by concreteness lints; the auditor would fire a boilerplate check on text that could equally describe a different spec; and at spec completion the distiller would write the per-spec and per-domain pages. No committed spec carries the section, `abcd spec` scaffolds none, the codes exist in no lint, and nothing writes the pages |
| Vocabulary registration (itd-37) | Every term introduced in a spec's vocabulary delta appears in the same spec in the registry that fits it — the canonical glossary or the reserved-vocabulary register. `VR001` is reserved for the check and unimplemented, so registration is enforced by review |
| Recovery humility (idea-2) | The disembark and embark surface docs carry the recovery-humility paragraph, and embark's closing imperative names hunting the originating session before trusting the lifeboat blindly |
| Surface discipline (sweep) | No `<verb> show`, `<verb> stats`, `<verb> view` or plain unfiltered `<verb> list` sub-verbs ship, and bare invocation renders state. `SD001` is reserved for the check and unimplemented, so the discipline is held by review — and the shipped tree does not satisfy it: `history show` and a plain `history list` both ship, and unfiltered `banlist list` renders identically to bare `banlist`, which is the redundancy the rule exists to forbid. The earned exception is a filter flag immediately adjacent to `list`: `capture list` with no filter exits 2 and asks for one, so the flag is the surface rather than a convenience, while `banlist list` does not, which is why it is a gap rather than an exception. Where bare invocation does not render is enumerated once, in [`../04-surfaces/README.md`](../04-surfaces/README.md#bare-invocation) |

> **Open question (adr-35):** where a mid-run interrupt checkpoint lands is
> undecided, which is why the *Disembark checkpoint* row is staged. adr-35 makes
> disembark read-only with respect to the source repository and moves the
> operations namespace to the operator level, but it does not say where a
> checkpoint goes. Three candidates and one exclusion: the operator-level voyage
> home, the destination, or the gitignored local tier; it may not be written into
> the source tree, which the read-only gate hashes. The retired logbook location
> is not a candidate at all — iss-73 retired it, and an armed detector fails the
> build on any non-test Go source under `internal/` that names it.
