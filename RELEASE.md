# Release 0.16.1 (2026-11-04)

`abcd drain` works the open issue ledger: it fixes what needs no decision, and routes what does to the place a person decides it. It lets through only the issues the repository's own recorded rule says a machine may touch alone, and sends each to the loop `abcd build` uses: one lane, one pull request, the run never approving its own pull request. An issue that needs a decision is handed back by kind: one that would change what a user sees becomes an intent draft seeded from the issue, for a person to plan; one that turns on a rule about trust or safety is flagged as needing a decision record, with the question stated; anything else is flagged with the home the decision belongs in. A lane that discovers a decision inside a mechanical fix stops, discards its work and hands the issue back the same way rather than guessing. What comes out is three lists: pull requests to review, drafts to plan, decisions to make. (itd-82)

> "I used to point the loop at the ledger and then hover, because the moment it hit something design-shaped it would either stall or, worse, decide it," said a product thinker who ran the first ledger drains by hand. (itd-82)

When several agent sessions build, review and test on one machine at once, abcd's load gate waits for the processor load to fall and refuses when the disk is nearly full; now it also reads how much memory pressure the machine is under. When the system reports memory pressure at or above the floor the person set (macOS's own pressure level, or on Linux the share of recent time tasks stalled waiting for memory), a preflight or a gated test run waits at the gate, bounded as the load wait is, instead of starting a test stage that would push the machine past its memory and stall every session on it. The wait says what it is waiting for, and a reading abcd cannot take lets the work through and says so, so the floor never wedges a run. (itd-2611012048006057)

Before an agent submits a filled-in form to abcd, it can do a practice run that checks the form and shows what would be written, writing nothing. Each of the fourteen commands that reads such a form takes `--dry-run`, and an agent sees a refusal before the form counts. (itd-2610301428390406)
