# Release 0.17.0 (2026-11-17)

**What you must change: the model classes take new names.** A person sets the whole model set a run uses: which model each class holds, how hard each class works, which classes review and which one judges. The four classes are named for what they are for (research, top, default and small), and every class runs at high effort unless the person says otherwise. With nothing configured, two reviewers run side by side at the research class and the default class, with the top class named as the judge for when they disagree. A configuration file written with the old names (`middle`, `below`, `smallest`, or `top` for the strongest class) is refused naming the new ones and is rewritten in them, and a run state this release writes is read by no earlier abcd. (itd-2611101419006280)

After a crash leaves a repository full of worktrees, branches, reservations and reports, one command says what is finished and what still needs a person. `abcd sweep` run bare changes nothing and lists every one with what it would do or why it would leave it alone; run with `--apply`, it clears only what is provably finished. Anything dirty, unmerged, locked by another tool or in use by a live session stays where it is, named with the reason, and a dead session's uncommitted work is saved as a patch before anything else happens. (itd-2610222214476887)

A drive that runs for weeks takes each new release of abcd itself, and nobody stops or restarts it. When a newer stable release is published, the drive notices at the next lane boundary, verifies it the way `abcd update` does, runs it read-only against the drain, proves it with the drive's full live check, and only then swaps it in and carries on from the drain's own state, saying in one line which version it moved from and to. A release that fails any step changes nothing, and one that cannot start the drive goes back to the kept copy. (itd-2611062149308723)

When the session coordinating unattended runs dies, the next session picks the runs up from what abcd wrote down, and nothing is started twice. `abcd implement resume` lists every run this machine drives: each lane's stage, each agent still alive or lost, the receipts that arrived while nobody collected them, the pull requests waiting and the work each lane left uncommitted. A waiting receipt is collected before any fresh agent starts, and uncommitted work is saved aside and named before anyone builds over it. (itd-2611041549461012)

An abcd question now reaches the person on its first try. Before an agent asks, abcd's question-writing agent checks the draft with the same rules the question check enforces at the moment of asking, fixes every fault and checks again, and returns only a question that passes; a question too long for one screen is split into numbered parts rather than cut. A repository sets how tall a question may be, how long a label may run and how much a description may say, and the check reports which file set each limit, while the rules that protect the person stay fixed in every repository. (itd-2610230756259215, itd-2610301914350541)

When an agent goes wrong, abcd tells it why and what to do instead; where no check can catch the mistake, abcd steers it in a short line as that work starts. An agent that tries an unsafe delete is refused and shown the safe form, in a sub-agent as much as in the main session, and the rules a prompt brings fit within what the host shows. (itd-2611041636196213)

An agent in a project that uses abcd learns how to use abcd from the abcd it is running. It asks `abcd explain` for one command's instructions and gets them in a few lines, with the exact form any input must take and one example that works, instead of reading a long page that may be older than the program. Every fact about a command is written once, in the program, and the pages are made from it and checked at every build. (itd-2610301346085246)

abcd writes down how each change landed. When a change reaches the default branch, abcd records whether a person approved it, the drain landed it under its rule, or it merged automatically after its checks passed, and which rule let it through, and `abcd landings` lists each one, so anyone can ask which changes landed with no person involved. (itd-2610301850454860)

Also in this release:

- Session and agent worktrees live in a machine-scoped store that abcd lists and reclaims, never beside the user's own projects (itd-2609091014076309)
- Sessions under any account, on any machine or in the cloud announce what they are doing through short fixed-form announcements on the shared remote, a person reads everyone's status with one command, and what is really a hold stays a reservation (itd-2609151838312703)
