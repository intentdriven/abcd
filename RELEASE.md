# Release 0.16.1 (2026-11-04)

When several agent sessions build, review and test on one machine at once, abcd's load gate waits for the processor load to fall and refuses when the disk is nearly full; now it also reads how much memory pressure the machine is under. When the system reports memory pressure at or above the floor the person set (macOS's own pressure level, or on Linux the share of recent time tasks stalled waiting for memory), a preflight or a gated test run waits at the gate, bounded as the load wait is, instead of starting a test stage that would push the machine past its memory and stall every session on it. The wait says what it is waiting for, and a reading abcd cannot take lets the work through and says so, so the floor never wedges a run. (itd-2611012048006057)

Before an agent submits a filled-in form to abcd, it can do a practice run that checks the form and shows what would be written, writing nothing. Each of the fourteen commands that reads such a form takes `--dry-run`. A practice run of `reading ingest` or `scribe ingest` leaves the capture verbs' own checks to the real write, so one that passes can still be refused there. (itd-2610301428390406)

`abcd drain` finishes its plan in this release. A trust or safety hand-back now writes its question onto the open issue, so a person finds the decision it owes without the summary, and a pull request a lane armed is watched in the merge queue: one left outside the queue is queued, and one the queue dropped is reported with the forge's reason and the failed check. The verb itself is older than this release. Each invocation makes one move, and the fix is made by an agent session or a routed runner driving the lane through `abcd implement step`. What comes out is pull requests to review, drafts to plan and decisions to make, with every other issue accounted for in the summary. (itd-82)
