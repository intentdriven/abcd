# Release 0.13.0 (2026-10-05)

On a Mac, abcd's own folder no longer gives the desktop search indexer work to do. It is named `~/.abcd.noindex`, a name the indexer passes over, so opening a working copy, writing a run log or keeping a transcript there sets off no indexing burst, and the computer stays responsive while abcd works. A new install starts with that name. An existing install stops at its next run and asks the person to rename `~/.abcd` to `~/.abcd.noindex` in a plain Terminal, naming the one command; after that, abcd runs as before. What search shows does not change, and abcd never touches the computer's own search settings. The upgrade guide, docs/how-to/upgrade-to-v0.13.0.md, walks the rename. (itd-2610030720038073)

When a person sets up a project with abcd, there is one conventions file to read and keep: AGENTS.md. abcd writes no separate copy of it for any tool. If the project already holds a tool's own file with the owner's words in it, abcd leaves that file exactly as it is and warns, loudly, that AGENTS.md stays hidden until the owner moves those words across; a file that only repeats or links to AGENTS.md is offered for removal, and goes only on a yes. A project set up earlier with a saved choice of CLAUDE.md stops at setup, and abcd explains the one setting to change. (itd-2610030814013772)

A question from an abcd agent is now something a person can answer without reading the record. Whenever an agent needs a human decision, it asks one thing at a time, quotes the thing being decided in full, carries one concrete example of what each answer would mean, and offers options that widen rather than recommend: no starred default, no recommended label, and the null answer always offered. Deferral is recorded as an answer; silence is never consent. (itd-201)

> "I was handed five design questions in one message, numbered, each three lines of record vocabulary," said a product thinker who answers for what their team ships. "I could not tell what any of them was asking me to choose between. Now I get one at a time, in words I use, with an example, and I answer in a click." (itd-201)

Whenever abcd asks you something, you can tell at a glance who the question is for, where you are in the interview, what is being decided, and what each answer means. Every question is built from the same parts: a short label, the thing being decided quoted in full in paragraphs and lists, one plain question, options that each say what choosing them means, and always a way to decide later. Nothing you need lives only in a side preview, and a question that breaks these rules is refused before it reaches you, naming the part and the limit. (itd-2610030810350727)

When a person connects a model service from inside their coding session, abcd works out the details with them instead of asking them to type each one. It asks for the service's address and, on a yes, looks up the models the service offers, suggests the ones the person already uses, and finds anything else when they type part of a name. It then shows one command, with every file that command will write, to paste into a terminal: nothing is set up from inside the session. Where the service needs the key first, that terminal step asks for it with the typing hidden, checks the pick with a real answer, and only then saves anything. (itd-2610030821294016)
